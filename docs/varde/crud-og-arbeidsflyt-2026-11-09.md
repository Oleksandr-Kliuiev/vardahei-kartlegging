# Что можно делать с опросниками, клиентами и людьми — и как сделать это удобнее

09.11.2026. Разбор кода + живая проверка на локальном стенде (`varde/tools/staging/up.sh`, сиды + импорт раунда 1).
Прод не трогался. Ничего не менялось в продуктовом коде.

Контекст, под который считался приоритет: кампания Haust 2026 — 48 клиентов (IT + BIO), два опросника
(`tryggleik` v3, `it-kartlegging` v1), раунды разговоров (Samtalar), семинары.

## 1. Что уже умеет система

### Опросники (`Skjema` / `Skjemaverkstaden`)

Самая зрелая часть. Полный жизненный цикл есть:

| Умеет | Где |
| --- | --- |
| 5 стартов: `client_survey`, `seminar_live`, `seminar_after`, `interview`, **копия опубликованного** | «Nytt skjema» |
| Версии: один черновик на опросник, `v N+1` из любой опубликованной, diff «Kva endra seg frå vN» | чип версии → «Versjonar» |
| Автосохранение по `content_hash`, 409 с выбором «мои / его», ⌘Z, копия в браузере | верстак |
| Вопросы: добавить, дублировать, удалить (с «Angre»), перетащить, Alt+↑/↓, взять из другого опросника («Hent») | тропа |
| Замок F1–F22: «Rett ordlyden» → «Rettskriving / Ny meining», откат к формулировке vN | карточка вопроса |
| Чек-лист публикации, одобрение языков, публикация удержанием, «Start ein runde med vN» | «Gjer klar til publisering» |
| Корзина: удалить черновик → восстановить → удалить навсегда | «Papirkorg (N)» |
| Комментарии к вопросу, «Brukt i», «Innsikt» прошлого раунда, «Del førehandsvising» | карточка вопроса |
| Правила Funn: новая версия с diff и предпросмотром, каталог Tiltak | «Funn-reglar» |

Жёсткие ограничения по дизайну (это правильно, менять не предлагаю): опубликованная версия неизменяема
(триггер БД + проверка в сервисе), `key` и `audience` не меняются, `interview`-гид не идёт в обычный раунд.

### Клиенты (`Kundar`)

| Умеет | Где |
| --- | --- |
| Создать (имя + число сотрудников) | «Ny kunde» |
| Изменить имя и число сотрудников | страница клиента → «Endre namn og tal tilsette» |
| Удалить — **только если к клиенту вообще ничего не привязано** | «Slett kunden» (проверка `ties`) |
| Страница клиента: Samtalar, «Over tid» (раунды, зоны, отчёты), Kontaktar, Funn + Tiltak, Seminar | `/admin/clients/<id>` |
| Добавить в раунд / семинар / раунд разговоров | из соответствующих разделов |
| Удалить все ответы клиента (+ его беседы) | Personvern → Sletting |
| Handover: зашифрованный ZIP с его данными, пароль один раз, 10 минут | Personvern → Eksport |

### Люди

Единой сущности «человек» нет — есть четыре независимых представления:

| Кто | Что хранится | Как появляется |
| --- | --- | --- |
| `Contact` | имя, e-post (natural key), компания, согласия | **только** сам человек через публичную форму записи на семинар |
| `Registration` | язык, версия согласия | там же |
| Респондент опроса | ничего; только число `population_snapshot` и инициалы, которые человек вписывает сам | — |
| `interviewees` в Samtale | JSON `[{role, name?}]` внутри беседы | диалог «Start samtale» |
| Админ Varde | только `AdminSession` | членство в группе Entra, вне Varde |

## 2. Чего нельзя — по тому, насколько это мешает кампании

### Мешает прямо сейчас (48 клиентов, два раунда, рассылка руками)

1. **Нет сегментов/тегов клиента.** Разделить «IT-kundar» и «BIO» нечем, хотя решение 02.11 требует
   отдельных когорт. Единственный способ — вручную отметить нужные галочки дважды.
2. **Нет поиска и фильтров нигде, где выбирают клиента.** Проверено на стенде с 48 клиентами:
   `/admin/clients` — 4142 px (≈4,6 экрана), 0 полей поиска; визард «Start ein runde» — 3822 px,
   48 чекбоксов подряд, кнопка «Start runden» далеко за сгибом. Поиск в админке существует ровно
   в двух местах: выбор клиента для беседы (`samtale-dialogar.tsx`) и поиск вопроса в верстаке.
3. **Нет массового заведения клиентов.** 48 клиентов кампании пришлось заводить скриптом через API
   (`docs/varde/kampanjar/haust-2026/README.md`, шаг 5). В UI — по одному.
4. **У клиента нет контактного лица.** А приглашение отправляет именно человек у клиента.
   `Contact` рождается только из регистрации на семинар: `POST /api/admin/contacts` не существует.
   Поле `role_at_client` показывается в UI, но записать его нечем (пишется только SQL-ом в тесте).
5. **Нет импорта содержимого опросника.** Кампанийные JSON грузились через `PUT .../versions/<id>` curl-ом.

### Мешает в работе, но обходится

6. **Клиента нельзя убрать из раунда** (нет `DELETE`), раунд нельзя удалить, дубликаты клиентов
   нельзя слить — а удалить дубликат, попавший хоть в один раунд, уже нельзя никогда.
   Признака «архивный/неактивный» у клиента нет вообще.
7. **Годовая проверка контактов — по одному.** «Stadfest» на строку; при 50 помеченных это 50 кликов.
   Кнопки «удалить» в списке нет: UI отправляет в Personvern → Sletting, где e-post надо набрать руками.
8. **Один и тот же человек живёт в 2–4 местах** и система об этом не знает: контакт клиента,
   участник семинаров, nøkkelperson в беседе — три независимые записи, связать нельзя.
   Поиска по человеку нет; чтобы понять, кто такой X, надо открыть клиента, каждый семинар и каждую беседу,
   и каждое раскрытие пишется в AuditLog.
9. **Перевод раунда на новую версию опросника** есть в API (`PATCH /api/admin/rounds/:id`), в UI нет.
10. **Одобрить нюношк нельзя, пока не дописан английский**: кнопка «Eg har lese korrektur» блокируется
    любыми issue, включая отсутствие en-текста в одном вопросе.
11. **Советы «Råd på slutten», их условия и `score_scale`** правятся только через технический JSON.
12. **Гид беседы (`interview`) нельзя переименовать через поля** — узел «Velkomen» для него скрыт,
    а название библиотека берёт именно оттуда. Остаётся JSON.

## 3. Дефекты, найденные живьём (дёшево чинятся)

| # | Что | Доказательство | Где |
| --- | --- | --- | --- |
| D1 | `localeCompare(..., 'nn')` в браузере не работает: Chrome не знает локали `nn` и падает в локаль браузера. `['Åsen','Ørsta','Æra','Bergen','Amla']` сортируется как **Æra, Amla, Åsen, Bergen, Ørsta**; с `'nb'` — правильно | проверено в браузере стенда | `surveys-page.tsx:38`, `samtale-start.tsx:29,37,116,154`, `samtale-tal.ts:35,43`, `samtale-tiltak.tsx:254` |
| D2 | `toLocaleDateString('nn-NO')` там же: в списке «Vel publisert versjon» даты выводятся на языке браузера (у меня — «9 нояб. 2026 г.») | скриншот визарда | `models.ts:59` |
| D3 | Сортировка клиентов идёт в Postgres (`orderBy: { name: 'asc' }`) с дефолтной collation: «Årdal» встал между «Amla» и «Balestrand», хотя Å — последняя буква алфавита | стенд с 48 клиентами | `apps/api/src/admin/admin.service.ts:18` |
| D4 | Копия опросника перезаписывает только нюношк-название; английское остаётся от источника | `editor.service.ts:193-195` | там же |
| D5 | Когда у опросника есть черновик, карточка показывает **только** «Utkast v3» — опубликованная версия, на которую отвечают клиенты, с карточки исчезает | скриншот библиотеки | `surveys-page.tsx:260-271` |
| D6 | На опубликованной (залоченной) версии поля `readOnly`, но выглядят как обычные: белый фон, обычная рамка, курсор `text`. Можно кликнуть и печатать без всякой реакции | computed styles на стенде | верстак |
| D7 | `role_at_client` рендерится в карточке контактов, но заполнить его нечем | grep: ни одного пути записи | `kunde-kontaktar.tsx:111` |

Серверные тексты (приглашения, отчёты) этим не задеты: Node 22 локаль `nn-NO` знает, проверено.

## 4. Предложение: как сделать удобным

### Волна A — кампания (самое дорогое по времени сейчас)

**A1. Клиент как рабочий объект.** Добавить в `Client`: `tags string[]` (или `segment`),
контактное лицо (имя, e-post, роль) и `default_lang` в UI (поле в схеме уже есть, UI нет).
Орг.номера в модели нет вообще — если он нужен, это отдельное поле.

**A2. Список клиентов.** Поиск по имени, фильтры «tag», «utan rundar», «aktiv/arkivert»,
сортировка через `nb`-collation. Признак `arkivert` вместо невозможного удаления.

**A3. Выбор клиентов везде одним компонентом** (как уже сделано в «Legg til kundar i samtalerunde»):
поиск + «Vel alle i IT» / «Vel alle i BIO» по тегу. Касается визарда раунда, формы семинара, раунда бесед.

**A4. Массовое заведение клиентов.** Вставить список построчно (`Namn;tal tilsette;tag`) → предпросмотр
с пометкой дублей по имени → создать. Это убирает скрипт из процесса кампании.

**A5. Контакт у клиента заводится админом.** `POST /api/admin/contacts` + форма на странице клиента,
с `role_at_client` и **без** согласия на приглашения (согласие по-прежнему только от самого человека).
Отдельно решить правовое основание — это к Asbjørn, см. §5.

### Волна B — порядок в данных

**B1. Убрать клиента из раунда**, пока `draft` и нет ответов. **Удалить пустой раунд.**
**B2. Слияние дубликатов клиентов** (перевесить `round_client`, `seminar_client`, `interview`, `contact`
на выжившего, запись в AuditLog) — либо, если это слишком, хотя бы «arkivert» из A2.
**B3. Годовая проверка контактов:** галочки + «Stadfest valde», и кнопка «Slett» прямо в строке,
ведущая в тот же поток подтверждения с подставленным e-post.
**B4. Поиск по человеку** (имя/e-post) одним местом, с той же записью в журнал, что и сейчас.
**B5. `PATCH /rounds/:id`** (смена версии опросника у раунда) вывести в UI раунда.

### Волна C — мастерская

**C1.** На карточке показывать и published, и draft одновременно (D5).
**C2.** «Lag utkast» и «Kopier» прямо с карточки и из панели «Versjonar» — API уже умеет форкать
от любой опубликованной версии, UI это не предлагает.
**C3.** Поиск/фильтр в библиотеке опросников; опросники в ⌘K (сейчас там только разделы, клиенты, раунды).
**C4.** Одобрение нюношка не блокировать недостающим английским.
**C5.** Импорт содержимого версии из JSON-файла (замена curl в кампаниях).
**C6.** «Papirkorg» доступна всегда, со своим адресом.

### Волна D — мелочи из §3

D1–D4, D6, D7 — каждая правка в одну–две строки, кроме D6 (стиль `readOnly`-полей) и D3
(сортировка: либо collation в запросе, либо сортировать на клиенте через `Intl.Collator('nb')`).
