## 1.16 Submission API (3 ч)

**Читать.** `ADR-006` «Отправка»; `ADR-017` пункт про журнал удалений; `ADR-024` строка «Replay POST живой отправки после forget»; `ADR-025` про `respondent_key`; `modules/privacy/response-store.ts` (1.8); `packages/rules/src/runner/*`.

**Шаги.** `modules/responses/submission.controller.ts` + `submission.service.ts`: `POST /api/runner/submissions` (bearer), тело — строгая схема `{submission_id: uuid, part: common | leader, lang, answers, free?, role?, duration_s?}` (лишние поля → 400). Сервер: RoundClient `open` и не истёк; версия — из раунда, не из тела; `lang` ∈ языков версии; `role` для leader обязателен и ∈ `leader_roles`; ответы — `normalizeAnswers` и `prune` (невидимое отброшено; для leader — только вопросы части leader); identification `initials` — ответ на identifier обязателен в обеих частях (иначе 400), переносится в `respondent_key`, из `answers` удаляется; `none` — ответа на identifier нет в версии, поле `respondent_key` в теле → 400 (строгая схема). `content_hash` = sha256 канонического JSON тела без `submission_id`. Одна транзакция: (1) Response с этим `submission_id` есть → тот же hash: 201 с тем же телом ответа, квота не расходуется; другой hash → 409; (2) tombstone с этим `submission_id` (ADR-017) → тот же hash: тот же идемпотентный 201 без вставки и без квоты; другой → 409; (3) квота — интерфейс `QuotaService.consume(roundClient, tx)` (до 1.17 — всегда разрешает); (4) вставка через `PrivacyService.store.insertParts` с `submitted_day` = сегодня (день); ответ `201 {ok: true, submission_id}`. IP не хранится; успешный запрос не логируется (0.6).

**Тесты.** Integration `test/responses/submission.test.ts`: повторный POST → 1 строка, тот же ответ, квота не расходуется (счётчик вызовов `consume`); тот же id с другим содержимым → 409; `submission_id` из tombstone с тем же hash → тот же 201 без вставки и без квоты, с другим hash → 409; «потеря ответа после commit» (первый POST закоммичен, клиент ответа не получил) → повтор 201; ответ на невидимый вопрос отброшен; идентифицированный раунд: `respondent_key` заполнен и нормализован у обеих частей, leader без identifier → 400, в `answers` identifier нет; анонимный: `respondent_key` в теле → 400, ключ null; закрытый RoundClient → 410; `submitted_day` — дата без времени.
**Приёмка.** Файл зелёный, ≥ 11 passed.
**Не входит.** Квоты (1.17), события SSE (1.25 подключит), `retention.forget` (1.31b; здесь tombstone через test support).
**Зависимости.** 1.15, 1.8.
