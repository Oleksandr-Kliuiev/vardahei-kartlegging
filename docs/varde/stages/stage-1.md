- **Golden** (1.2c, `varde/tools/parity/golden/`): значения, снятые со старого дашборда и старого сервера, запущенных из временной копии `kartlegging/` (без `data/` и без `private/runde1.js`) на синтетических данных двумя прогонами (п. 11): зоны, ключевые вопросы, FUNN, сравнение с раундом 1, «Svar per tilsett» (оба опросника), таблица руководителя, распределения, пути и советы runner, `analyse.csv`. `golden/manifest.json` — sha256 fixtures и tree-hash `kartlegging/`; `pnpm parity:golden --check` в job `e2e` пересоздаёт golden и сравнивает. Golden меняется только вместе с изменением kartlegging, причина — в evidence.
- **Согласованные отклонения паритета** (тесты паритета перечисляют их явно как исключения с номером; новое отклонение — замечание приёмки, кодер описывает его в evidence с причиной):
  1. Подавление дополнительных групп (итог − видимые группы < k) и малые клиенты (n < 3) только в сумме — сверх `minGruppe` старого дашборда (ADR-021). Полные данные админ видит в классе `rows`.
  2. При фильтре «alle» таблица руководителей и простые leader-правила — из `leaders_all` как «X av Y leiarar» без имён клиентов; F12×B13 при «alle» — число клиентов без имён (ADR-020, ADR-026).
  3. Экспорт Master_Analyse (1.30b) — формат `/api/analyse.csv` PR #1 без строк `Del = B` (часть руководителя — только leader-канал, ADR-021/ADR-025), один файл на раунд (старый — один файл на оба опросника); сравнение с golden — как мультимножество строк (1.30b); вид по людям — отдельным файлом. CSV `rows` для команды (1.30) — только common (часть руководителя — leader-эндпоинт и handover), время — день, `duration_s` вместо `sekund`, плюс колонка `submission_id`; старый `/api/svar.csv` отдаёт все вопросы, включая часть B, `tid` и `sekund`.
  4. Интро runner — утверждённые тексты уведомления v2 (0.18) по режиму вместо `fakta2`; часть руководителя — с `notice.common.leader_not_anonymous`.
  5. Панель прогресса: ячейки «обрыв по вопросу» с < 3 сессиями скрыты; строк по сессиям нет (ADR-021).
  6. Время ответа — только день; `sekund` → `duration_s`; IP не хранится. Поэтому порядок строк внутри одного дня в экспортах Varde не воспроизводит старый (старый сортирует по полному `tid`).
  7. Одна старая отправка → две Response (common и leader) со своими `submission_id` (ADR-006, ADR-024).
  8. Новые коды ≥ 128 бит на RoundClient; старые ссылки и плакаты → «Kartlegginga er avslutta» (ADR-009).
  9. Импорт не пересчитывает путь показа (как старый дашборд); неизвестные id вопросов и вариантов отбрасываются, как в `valider()`, число — `dropped_answers` в manifest.
  10. Демо-режим старого дашборда (`demodata()` без сервера) не переносится.
  11. Состав строк. Varde считает только строки, принятые импортом (ADR-024: без `id`, повтор `id`, неизвестные `versjon` или `k` → `rejected`), а строки KI 2026-10-12 без K0 кладёт в отдельный анонимный раунд (§10 п. 1). Старый дашборд и `/api/analyse.csv` берут все строки файла и сводят обе версии KI в один вид (`dashboard.html::rader()` фильтрует только по `skjema`; `analyse-eksport.js` выгружает KI 2026-10-12 с пустым «Initialar»). Поэтому golden снимается двумя прогонами старого сервера (1.2c): (а) fixtures без краевых строк и без строк KI 2026-10-12 — эталон раундов tryggleik и KI 2026-10-13 и `analyse.csv`; (б) только строки KI 2026-10-12 — эталон анонимного раунда (распределения, KI-блоки, FUNN, цитаты). На проде строк KI 2026-10-12 ожидается 0 (§3); отклонённые строки и строки анонимного раунда видны в manifest и учитываются при сверке 1.35 шаг (4).

Правило 6 ADR-021 остаётся в `release()` (unit-тест 0.15b) для будущих внешних каналов прогресса. Альтернатива (+2 ч в 1.20): хранить последнюю показанную версию ячеек прогресса и считать разности против неё, с тестом «обрыв 2 → 3 → carry-forward до Δn ≥ k».
