## 0.14 Eval harness и слепая оценка носителей (3 ч)

> **Упрощено 13.10 (решение Oleksandr, облегчённый процесс):** 5 брифов × одна модель (`claude-opus-5-5`) × один прогон; оценивает Oleksandr сам по той же шкале (смысл, естественность нюношка, минуты правки, критические ошибки); слепая оценка Asbjørn и Bjarte и сравнение двух моделей не проводятся. Порог pass: медианы ≥ 4, 0 критических ошибок у ≥ 4 из 5 брифов. Остальной текст задачи — для полной версии, если понадобится.

**Читать.** `ADR-010` решение, строки 3 (шкала, пороги, contingency) и «Последствия»; `ADR-018` строки про eval и тройку `(prompt_hash, model, briefs_version)`; `ADR-005` (frozen — в брифах таких текстов нет); `PRINCIPLES.md` §3 (критерии вопроса: без жаргона, ≤ 25 слов, «veit ikkje», без продуктов); `packages/schema/src/i18n/nn-stoplist.ts`.

**Кодер.**
1. `tools/eval/` (`@varde/tools-eval`): `briefs/v1/*.md` — 10 брифов на нюношке (черновики кодера, утверждает Oleksandr; формат: тема, аудитория, цель опроса, 2–3 ограничения; пример — «backup på hotellet»), `briefs_version` = hash папки; `prompt/v1.md` — системный промпт умения «черновик опроса по брифу» с требованиями PRINCIPLES §3 и JSON-схемой выхода (`packages/schema/src/survey-draft.ts` минимальная: вопросы с текстами nn, тип, варианты; стоп-список продуктов), `prompt_hash` = sha256 файла.
2. `run.ts`: официальный SDK `@anthropic-ai/sdk`; для каждого брифа × 2 модели (`claude-opus-5-5`, `claude-sonnet-5-5`; список в `tools/eval/models.json`, ключ только из env `ANTHROPIC_API_KEY`) × 2 прогона — structured output по схеме (`output_config.format`), adaptive thinking, `effort` явно (в метаданных), без принудительного `tool_choice`; `stop_reason: "refusal"` → критическая ошибка `refusal`; в `tools/eval/runs/<briefs_version>/<prompt_hash>/<model>/<brief>-<run>.json` сохраняются **только** содержимое ответа модели и метаданные (`model`, `effort`, `stop_reason`, `usage`, стоимость, время) — никаких заголовков запроса и ключей (коммитятся как записанные fixtures); автопроверки: схема, язык (`findBokmal` из `nn-stoplist`, список при необходимости расширяется в том же модуле), ≤ 25 слов на вопрос, стоп-список продуктов, «veit ikkje»/skip присутствует.
3. `blind.ts`: собирает пакет для носителей — для каждого брифа **все четыре** выхода (2 модели × 2 прогона) с метками `A`–`D` по случайной перестановке на бриф (ключ перестановки в `blind-key.json`, носителям не показывается), лист оценки `scores/<name>.csv` с колонками `brief, variant, meaning_1_5, naturalness_1_5, edit_minutes, critical_errors (список кодов: wrong_language | mixed_nn_nb | invented_fact | product_name | schema_violation | refusal)`; инструкция носителю на нюношке (`scoring-guide.md`).
4. `score.ts`: читает CSV обоих носителей, снимает ослепление, считает по модели; правила агрегации (зафиксированы здесь и в fixture-тестах): медианы смысла и естественности — по всем оценкам модели (10 брифов × 2 прогона × 2 оценщика = 40); бриф считается «правка > 5 мин», если медиана `edit_minutes` по его 4 оценкам (2 прогона × 2 оценщика) > 5; у брифа «0 критических», если ни один оценщик ни в одном прогоне не отметил критическую ошибку; pass по ADR-010 (медианы ≥ 4, ≤ 2 брифов > 5 мин, 0 критических у ≥ 8 из 10); при pass обеих моделей — обе суммы медиан и стоимость на бриф, выбор за Oleksandr; отчёт `docs/varde/evidence/stage-0/0.14-report.md` с тройкой `(prompt_hash, model, briefs_version)`, таблицей и решением pass/fail; выбранная Oleksandr модель → `varde/config/model.json` (`{model, effort, prompt_hash, briefs_version, report}`); при провале обеих — раздел «contingency: другая модель Anthropic или дополнительный провайдер, свой ADR» и G0 остаётся закрытым.
5. CI: `tools/eval/test/score.test.ts` на fixture-CSV — кейсы pass, fail по медиане, fail по «> 2 брифов с медианой минут > 5», fail по критической ошибке, отмеченной одним из двух оценщиков в одном прогоне; `run.test.ts` на записанных ответах (автопроверки воспроизводимы, живых вызовов нет; пропускается с явным `skipped: no recorded runs`, пока папки `runs/` нет; дополнительно проверяет, что ни в одном `runs/**/*.json` нет ключей `x-api-key`, `Authorization`, `sk-ant-`); `report-triple.test.ts`: пока `model.json` нет — `skipped: no model.json`; если есть — отчёт с той же тройкой существует, иначе fail (заготовка проверки 2.13).

**Oleksandr и носители.** Oleksandr утверждает брифы и запускает `run.ts` с ключом Anthropic API; Asbjørn и Bjarte заполняют свои CSV (≈ 2 ч каждый), не видя, какой вариант от какой модели; Oleksandr коммитит CSV и запускает `score.ts`.

**Приёмка.** `pnpm --filter @varde/tools-eval test` зелёный (на коммите кодера — с `skipped`); после прогона: `0.14-report.md` с решением pass/fail и тройкой; при pass `varde/config/model.json` заполнен и `report-triple` зелёный без `skipped`; записанные runs и CSV в репо (hash в evidence). Evidence `docs/varde/evidence/stage-0/0d-evidence.md`: commit, модели/усилия, статус входов (Anthropic, брифы, носители), чек-лист 0.13 в строгом режиме, результат 0.14; G0 открывается только при pass и чек-листе без `pending`.
**Не входит.** Умение в продукте (2.8), адаптер (2.6), живой eval в CI (ADR-018: по триггеру, 2.13).
**Зависимости.** 0.13 (организация, доступность моделей, место обработки); входы — брифы, носители, ключ Anthropic API у Oleksandr.
