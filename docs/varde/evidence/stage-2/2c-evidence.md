### Независимое ревью (агент, только чтение) — найдено и исправлено

- Повторное открытие черновика из кэша давало старую копию и хеш: следующая правка получала 409 против самой себя, а «Lagre mine over» затирал прошлые правки. Теперь мастерская открывается только со свежих данных сервера (после незавершённого сохранения), каждое сохранение кладётся в кэш.
- Сервер считал заголовок раздела изменением F-вопроса: перенос F-вопроса в начало раздела или переименование раздела блокировали публикацию без возможности отметить. Сервер теперь сравнивает без заголовка раздела (тест API, мутационная проверка).
- Восстановление копии из браузера шло с новым хешем и могло молча затереть чужое сохранение; теперь копия хранит свой хеш и идёт через выбор при конфликте.
- Уход из мастерской внутри приложения в первые 0,7 с терял набранное; теперь сохраняется.
- Два ожидающих сохранения уходили с одним хешем (ложный 409); теперь сохранения строго по очереди.
- Телефон держался за номер шага: при переносе вопроса выделение в тропе прыгало на соседний; теперь держится за сам вопрос.
- Смена вопроса в правиле условия стирала правило; удалённый ID мог достаться новому вопросу («Angre» тогда молча ничего не делал); ⌘Z работал в опубликованной версии; безымянный первый раздел при перемещении сливался с соседом. Всё исправлено, на каждое — тест; ключевые проверены мутациями (тест падает на старом коде).

### Приёмка xhigh (агент, отдельный worktree) — «принять с исправлениями»

- **H1, блокирующая — исправлено (cad6027, уточнено по ревью в 15fb1cd).** Раунд на версии, опубликованной в мастерской, получал только автоматические распределения: без зон, без FUNN, с пустым сравнением с раундом 1. Теперь версия из мастерской берёт определения шаблона для вопросов, которые значат то же самое (`metrics/same-meaning.ts`): F-вопрос с замком — тот же anchor и та же структура (слова меняются только как отмеченная орфография); вопрос без замка — точно такой же, кроме заголовка раздела (изменение его слов ничем не отмечается, поэтому это новый вопрос); то, от чего вопрос зависит (условие, `choices_from`), тоже держится; вопрос руководителей — при тех же ролях руководителей. Для остальных вопросов — свои распределения, одна серия на вопрос. Орфография F-вопроса сохраняет всё; «Ny meining» убирает то, что читает вопрос (у F3–F19 — зону, среднее и долю критичных), пока не будет новой версии метрики. Раунд, который уже выпускался, держит набор метрик первого выпуска (правило 4 из 1.4c). Тест «те же ответы на версии из мастерской дают то же сравнение, что на сидовой» был красным — зелёный; мутации каждого условия (anchor, двойная серия, точное совпадение без замка, зависимости, роли руководителей) ловятся.
- **M2 — исправлено.** «Orthographic» сервер принимает только для правки слов (ответы, баллы, тип и условия те же); F-вопрос не может потерять `frozen`.
- **L1 — исправлено.** Сервер не публикует пустые обязательные тексты ни на одном языке опросника (раньше держал только интерфейс).
- **L2 — исправлено.** Структурные вопросы получают пустой текст на bokmål, если он есть в опроснике.
- **M1 — не исправлено (безопасно).** После «Ny meining» у одного F-вопроса сравнение с раундом 1 пропадает целиком, а не по одному вопросу (раунды сравниваются только при одинаковом наборе якорей). Текст «Ny meining» в мастерской теперь говорит, что сона и funn по вопросу не считаются.
- **L3 — не исправлено.** Ключи текстов письма, фактов и советов идут по номеру: вставка абзаца отмечает следующие как «изменённые после одобрения».
- Для прода: 2.15 уже на проде. Если в мастерской опубликовали новую версию tryggleik или ki и запустили на ней раунд, у этого раунда сейчас нет зон, FUNN и сравнения. После выкатки раунд, который ещё не выпускался (открытый, без промежуточного release), считается по новым правилам; раунд, который уже выпускался, держит свой набор метрик (правило 4) и остаётся без зон. Перед выкаткой стоит проверить SQL-запросом, есть ли такие раунды.

### Что сделано
