# privacy: «alle» сам по себе — клиенты × роли вместе (правило 7) и итог «Før og etter», 16.10.2026

Ветка `varde/privacy-2d` от `main` 888668e (после merge `varde/privacy-rc`). Закрывает пункт BACKLOG «privacy, до этапа 4 (найдено 16.10 при закрытии I1)». Кодер — Claude Opus 5.5. Миграций нет, данные не меняются. Экраны меняются в редких раундах (ниже) — по решениям Oleksandr 16.10.

## Путь

1. Внутри `all_clients` ячейки `client:*` и `role:*` — маргиналы одной таблицы клиент × роль, а подавлялись независимо. Пример задачи: k0 (1, r1), k1 (4, все r1), k2 (1), k3 (1), k4 (3) — в r0. Видны `all` 10, `role:r1` 5, `client:k1` 4 → k0 = 5 − 4 = 1.
2. `clientGroup` для группы «все клиенты раунда» отдавал итог раунда, даже если кто-то скрыт. «Før og etter» на проекторе + отчёт клиента в раунде из двух клиентов: 6 − 5 = 1.

## Решения Oleksandr 16.10 (BESLUTNINGER, ADR-021)

- На разрезе скрывается **ячейка роли**; клиенты и итог остаются. Синтетика (3000 раундов): 37 раундов с утечкой; «только роли» — 55 доп. скрытых ячеек и 0 клиентов; «меньшая ячейка» — 83, из них 52 клиента; «сначала клиенты» — 82 / 62.
- Итог «Før og etter» для всех клиентов — скрывается **только при утечке** через отчёт скрытого клиента (~43 % синтетики против ~68 % при «скрыт любой клиент»).

## Механизм (`privacy/cross.ts`)

Граф: видимые клиенты и роли — свои узлы; скрытые клиенты — один узел, скрытые роли и ответы без роли — другой; рёбра — непустые группы клиент × роль. Комбинация a·итог + Σα·клиент + Σβ·роль даёт на ребре (c, r) коэффициент a + α_c + β_r; 0/1 на всех рёбрах раскладывается на «разрезы» X: роль в X ⇒ все её клиенты в X; S = рёбра из клиентов X в роли вне X; n(S) = Σ маргиналов клиентов X − Σ маргиналов ролей X. Поэтому «нет разреза с 0 < |n| < k» ⇔ «ни одна линейная комбинация видимых ячеек не определяет набор групп < k». Перебор: подмножества узлов ролей (2^ролей) + subset-sum по остальным клиентам. Без итога скрытые узлы связаны (на одной стороне); итог, равный сумме видимых клиентов (ролей), учитывается.

Две выдачи (разности): набор определён в обеих ⇔ лежит в пересечении пространств. У каждой компоненты связности структуры свой итог и свой сдвиг потенциала, поэтому поиск идёт по компонентам: скрытые классы двух выдач сливаются только внутри компоненты, а общий для выдачи коэффициент итога (−1, 0, 1 при видимом итоге) перебирается явно; суммы компонент складываются. (Первая версия сливала классы по всему графу и ошибалась на несвязных структурах — находка B1 приёмки.) Модель атакующего: знает структуру (у какого клиента какие роли), но не кто ответил между выдачами; структура — текущая (ответы только прибавляются; меньше рёбер — больше разрезов, т. е. проверка строже). Группа, которой не было в выдаче, читается как 0 (как в правиле 2).

Встраивание:
- `release.ts`, правило 7: для блоков `all_clients` с ролями и клиентами нужен `opts.cross` (иначе `ReleaseRejected`); шаг идёт после неподвижной точки правил 1–3. Текущая таблица — «текущие» значения (свежие и перенесённые, равные текущему); разрез → скрыть роль. Разность с каждой прошлой выдачей `all_clients` (своя история, не связанная `round_client`) → перенести ячейку разреза (роль, затем клиент, затем итог — как правило 2); уже перенесённую — скрыть.
- История выдач — от старой к новой (Prisma: по `superseded_at`); перенесённое значение прошлой выдачи — уравнение той выдачи, из которой оно взято; удалённая (сохранённая) группа не считается текущей.
- `view-cells.ts` (живой вид) — `hideJointRoles` с кэшем по одинаковым блокам; без структуры метрики все роли скрываются; больше 12 ролевых узлов — роли скрываются (fail closed).
- `PrivacyService.allClientsCells` — ячейки `all_clients` и ячейки каждого клиента (`all`, `role:*`) одним чтением строк; структура — только вход проверки; lint `varde/round-client-exits` пускает метод только в `metrics.service.ts` (как `computeCells`).
- `cohort.ts`, `roundTotal`: итог группы «все клиенты» скрыт, если в этой метрике итог − Σ видимых клиентов − выданный отчёт (`ownCells`) скрытого в ней клиента ∈ (0, k). Живые ячейки клиента в расчёт не идут: их видят только админы.

## Остаточные риски (BACKLOG)

- Атакующий, который знает, кто ответил между двумя выдачами «alle»: в синтетике (600 раундов с 2–3 выдачами, решатель по эпохам) на `main` 103 раунда с утечкой (клиенты 29, роли 23, вместе 51), на ветке 67. Это предел правил 2–3 (сравнивают одинаковые ячейки, а не старый итог с новой ролью); закрыть можно только с таблицами прошлых выдач, которые privacy не хранит.
- Разности, трёхуровневые внутри компоненты, при нескольких компонентах, скрытых с обеих сторон в обеих выдачах с итогом: пример повторной приёмки на уровне `smallCut`; через `release()` не воспроизведён (исчерпывающий оракул, 11 299 раундов).
- Удаление ответов между двумя выдачами: вне модели (оракул приёмки — 2 из 5365 пар видов).
- Итог «alle» на любом экране, который видят люди клиента, вместе с отчётом клиента выдаёт скрытых клиентов (то же, что п. 2, вне «Før og etter»); сейчас «alle» — только у админов. Проверить каналы этапа 4.
