**1.12, тесты без случайных падений.** Четыре падения при первом локальном прогоне разобраны:
- `1a-completeness` «five deletions…» и `forget` «released snapshots remain…» упирались в общий тайм-аут 60 с (нагрузка Mac); у обоих теперь свой тайм-аут 240 с. Второй тест 1a падал вслед за первым (тот оставил раунды наполовину изменёнными);
- `runner-live` «sixty phones»: **настоящая причина — в коде.** Каждый ответ клиента берёт блокировку строки `round_client`, 60 телефонов встают в очередь, а у транзакции Prisma по умолчанию 2 с на получение соединения (пул из 8) и 5 с на всё. Хвост очереди получал 503. Теперь `maxWait` 15 с и `timeout` 20 с для транзакции приёма ответа. Это поведение живого семинара, а не только теста. Причину я вывел из кода и из условий падения, воспроизвести 503 отдельно не удалось;
- `seminar-funn` e2e (карточка «Funn» на телефоне на 122 px вместо ≤ 92): локально воспроизводилось редко (6 и 10 повторов подряд под полной загрузкой прошли), на GitHub падало каждый раз. Диагностика из GitHub Actions: страница не упирается в конец, карточка оказывалась на 46 px ниже, чем после `scrollIntoView` с `scroll-margin` 76, то есть вёрстка выше неё меняла высоту уже после прокрутки. Исправлено в продукте (`kunde-funn.tsx`): карточка удерживается наверху, пока вёрстка не устоится (до 1,5 с или до первого колеса, касания, клавиши, клика). Тест остался с прежним утверждением.

**1.3, вход.**
- Origin: изменяющий запрос (POST, PUT, PATCH, DELETE) к `/api/admin/*` и `/auth/*` с чужим `Origin` (в том числе `null`) получает 403 до проверки сессии. Запрос без `Origin` не из браузера и проходит как раньше (у Playwright и скриптов его нет). Совпадение: хост запроса или хост `PUBLIC_URL`. Это закрывает запросы с соседних `*.vardahei.tech`, для которых SameSite=Lax не защита;
- cookie сессии — `__Host-varde_session` (Secure, Path=/, без Domain): сосед не может ни поставить, ни перезаписать её. **При выкатке все администраторы входят заново один раз;**
- idle: Entra-сессия живёт 1 час без запросов (`SESSION_IDLE_SECONDS`, по умолчанию 3600) и в любом случае не дольше абсолютных 8 часов. Окно сдвигается не чаще раза в 5 минут, без миграции (используется `expires_at`, cookie живёт все 8 часов). Break-glass-сессии не затронуты;
- проверка `ping` открытого потока событий окно не сдвигает (`resolve(request, false)`), иначе оставленная вкладка держала бы сессию все 8 часов; сдвигает только запрос;
- `VARDE_OIDC_ISSUER` при `NODE_ENV=production` — приложение не стартует. На VPS переменной нет (проверено 27.10 только на наличие строки), образ ставит `NODE_ENV=production`.
**Не проверено в Entra:** что группа «Varde admins» входит только с MFA (Conditional Access) — это в портале, не в коде.

**1.4, лимиты публичных точек.**
- у каждого round client своё окно 10 минут (150), у семинара для регистрации (100), у live round client (1500); общие окна остались верхней границей. Конфиг отвергает окно ссылки больше общего. Одна утёкшая ссылка тратит только своё окно;
- IPv6 считается по /64, IPv4-mapped — как IPv4. Ключ — только в памяти процесса, как раньше;
- **Не сделано: базовый лимит на Caddy.** В общем Caddy нет модуля rate limit, нужна пользовательская сборка или плагин, это Caddy соседей (Atlas).
