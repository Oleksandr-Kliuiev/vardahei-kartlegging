# Этапы сборки Varde

Принято: план 11.10 одобрен Astra и Fable, delta 12.10 (ADR-025, ADR-026) одобрена 13.10 Astra и чистой сессией Fable (`astra/delta-12-10-approval.md`); решения Oleksandr 12–13.10 внесены как решённые (анонимность — выбор перед стартом опросника, вариант B для всех раундов, правило (a) для руководителей, бессрочное хранение с удалением и возвратом по требованию, букмол по переключателю); открытых пометок нет. Задача = 1–3 часа работы Opus 5.5 (medium) с тестами, один коммит. Перед этапом автор пакета пишет `stages/stage-N.md` с теми же задачами, обязательными тестами и списком «не входит» (этап 0 — Fable, `stages/stage-0.md` и `stages/stage-0/0a–0d.md`; с этапа 1 — Claude Opus 5.5, Fable и Astra только в крайнем случае, решение 13.10; этап 1 — `stages/stage-1.md` и `stages/stage-1/1a–1c.md`). Размер: S — дни, M — неделя, L — две и больше. Колонка «ч» — часы кодера; календарное ожидание внешних входов — в таблице ниже, не в часах.

## Протокол checkpoint

- Checkpoint закрывается пакетом доказательств `evidence/stage-N/<cp>-evidence.md` (вне манифеста одобренного артефакта: в манифест входят только `ARCHITECTURE.md`, `PRINCIPLES.md`, `STAGES.md`, `adr/`, `stages/`; команда — `stages/stage-0.md` §10): artifact hash (commit), манифест одобренного пакета этапа и вычисленный на commit, команды проверки с ожидаемым выходом, hash использованных fixtures, список согласованных отклонений паритета, статус внешних входов, перечень инвариантов, проверенных в этом checkpoint. Отчёты, чек-листы и скриншоты кодера — там же, в `evidence/stage-N/`.
- Приёмка — облегчённый процесс (решение Oleksandr 13.10): главная проверка — зелёный CI и проверка diff и ключевых команд оркестратором; чистая сессия Opus 5.5 (xhigh) — только для рискованных частей (приватность, вход, импорт данных, переключение kartlegging) и один раз в конце этапа; minor исправляются без повторной проверки, повторная — только после blocking/important; отдельные пакеты этапов дальше не пишутся — кодер работает по строкам STAGES.md, ADR и короткому заданию оркестратора.
- Зависимая работа следующего checkpoint не начинается до зелёного CI и merge предыдущего (а для рискованных частей — до приёмки чистой сессией).
- Инварианты проверяются в checkpoint, где появляется соответствующий код; последняя задача каждого checkpoint — его тесты инвариантов.
