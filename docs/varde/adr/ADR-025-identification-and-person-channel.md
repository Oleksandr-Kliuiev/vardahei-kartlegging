# ADR-025: Идентификация — свойство версии шаблона; канал `person` для идентифицированных раундов

Статус: Proposed (delta 12.10, автор Fable; на одобрение Astra и чистой сессии Fable). Граница доверия для идентифицированных раундов решена Oleksandr 12.10 (вариант B спора 21); для анонимных раундов спор 21 открыт — [O3], ADR-021.

## Контекст
План 11.10 считал анонимность свойством всей системы: Response не знает человека, любая выдача с разбивкой идёт через `privacy` с k = 3 (PRINCIPLES §6–7, ADR-021). 12.10 продукт изменился: опросник по безопасности спрашивает обязательные инициалы (F1, «2 første og 3 siste»), дашборд показывает строку на человека (инициалы, snittscore, зона, зона в раунде 1 по паре «фирма + инициалы»), а респондентам обещано: «Svara per person ser berre Vardahei IT. Bedrifta får eit samla bilete utan initialar.» KI-опросник остался анонимным; два опросника не смешиваются. Порог `minGruppe = 3` в дашборде по-прежнему скрывает малые роли в обоих опросниках. Решение Oleksandr 12.10: для опросника по безопасности действует вариант B спора 21 — трое сотрудников Vardahei IT видят ответы по каждому человеку в приложении, клиент получает сводку без инициалов.

## Решение
- **Признак идентификации живёт в `TemplateVersion.identification: none | initials`** и публикуется вместе с версией (неизменяем). При `initials` ровно один вопрос версии помечен структурным полем `identifier: true` (тип `text`, одна строка, ≤ 8 символов); при `none` такого вопроса нет — схема (1.1) отклоняет оба нарушения. `Round.identification` копируется из версии при открытии первого RoundClient и дальше не меняется (как `template_version`, ADR-022). Шаблон по безопасности — `initials`, KI-шаблон — `none`.
- **`Response.respondent_key`** — отдельная колонка (нормализованные инициалы: trim, верхний регистр, ≤ 8 символов), заполняется только серверным normalizer (`rules/runner`, ADR-006) из ответа на identifier-вопрос; в `answers` этого ответа нет никогда (тест). В анонимных раундах `respondent_key` всегда null; присланное поле identifier отклоняется; ограничение БД проверяет, что non-null бывает только в раундах с `identification = initials`. В идентифицированном раунде обе части одного человека — common и leader — несут один и тот же `respondent_key` (runner берёт его из черновика и шлёт с обеими отправками; leader-отправка без него → 400): иначе удаление по человеку (ADR-017) не охватит часть руководителя. Это атрибут человека, а не ключ связи отправок: FK и общего `submission`-ключа между частями по-прежнему нет (ADR-006, ADR-024), канал `person` показывает только общую часть, канал leader — только часть руководителя (ADR-021 [O4]); в анонимных раундах обе части без ключа. Никаких Contact, Registration, ProgressEvent, IP; время — день; ProgressEvent остаётся анонимным по сессии. Связь между раундами по человеку — пара `(client, respondent_key)` между идентифицированными раундами одного семейства якорей; связь приблизительная (однофамильцы по инициалам, опечатки) и так и называется в UI, как сейчас («same initialar i same bedrift»).
- **Два класса выдачи в `privacy`.** `aggregate` — всё, что было: k = 3 на группу, подавление дополнительных групп, история выдач в `privacy.release()`; применяется в обоих режимах ко всем каналам (дашборд, CSV, отчёт, Atlas, ассистент). Порог в идентифицированных раундах не снимается (предложение ENDRINGAR п. 1 «k только для анонимных» не принято): агрегатные виды — то, что уходит клиенту и в отчёт, и это паритет с `minGruppe`. `person` — строки по человеку (`respondent_key`, роль, ответы общей части, snittscore, зона, зона предыдущего идентифицированного раунда): только для раундов с `identification = initials`, только админ-сессия, по одному клиенту или по всем клиентам, каждое чтение в AuditLog (кто, объём, когда) в одной транзакции с ответом; для анонимного раунда канал отвечает 404. Канал `person` никогда не попадает в снимки, контекст ассистента, Proposal, ObservationOutbox, автоматический отчёт и клиентский CSV — ни `respondent_key`, ни инициалы, ни строки.
- **Кто что видит.** Трое админов — `aggregate` + `person` + leader-эндпоинт (ADR-021); клиент — «samla bilete utan initialar»: агрегаты под k по клиенту, вопросам и зонам, выводы, сравнение с прошлым раундом, отчёт 5.1 — без инициалов, без строк по человеку и без строк руководителя; ассистент, Atlas, CSV для клиента — только released-агрегаты. Экспорт Master_Analyse для шефа (1.30b) — канал `person`.
- **Граница доверия по режиму раунда.** Идентифицированные раунды — вариант B (решение 12.10): трое админов доверены под AuditLog, живые агрегаты с порогом, канал `person`; raw-экспорт общей части как отдельное исключение в таких раундах не нужен — его покрывает `person`. Анонимные раунды (KI) — A или B по ADR-021, [O3]. Один модуль `privacy`, режим выбирается по `Round.identification`; таблица отрицательных тестов — объединение таблиц ADR-021 и этого ADR.
- **Сравнение по людям** считается из raw (Response) только в канале `person`; в снимках его нет. Полнота снимков (ADR-020, тест 1.11) относится к `aggregate`: после удаления raw агрегаты, FUNN и сравнение по клиентам и вопросам считаются из снимков; канал `person` при этом исчезает — это ожидаемо и проверяется тестом, не считается потерей.
- **Хранение и удаление** — ADR-017: бессрочно, удаление только по явному запросу (по клиенту, по человеку — обе части, или по найденным человеком строкам анонимного раунда) под AuditLog; журнал удалений не даёт удалённому вернуться через restore, импорт и rollback.
- **Уведомление респондентам (0.18)** называет: для опросника по безопасности — инициалы, кто видит ответы по человеку (трое сотрудников Vardahei IT), что клиент получает сводку без инициалов, критерий хранения (ADR-017), роли сторон [O5]; для KI — анонимность и границу доверия по [O3]; для части руководителя — «ikkje anonymt» [O4].

## Альтернативы
Признак на Round, не на версии (отклонено: identifier-вопрос и текст обещания — часть шаблона; разные режимы одного шаблона ломают сравнение по людям). Хэш вместо инициалов в `respondent_key` (отклонено: дашборд и Excel шефа показывают инициалы; хэш скрывал бы их только от тех, кто уже видит строки). Связь через Contact (отклонено: Contact — персональные данные семинаров с согласием, инициалы — не контакт). `k` только для анонимных раундов (отклонено, см. выше). Раздельный `privacy` на режим (отклонено: два кода выдачи — две поверхности обхода).

## Последствия
PRINCIPLES §6–7 и ARCHITECTURE §4–5 переписаны; ADR-021 ограничен анонимными раундами и правилом leader. Тесты: identifier не попадает в `answers`; `respondent_key` null в анонимном раунде и отклонение присланного identifier; канал `person` → 404 для анонимного раунда, 401 без админ-сессии, AuditLog в одной транзакции; контекст ассистента, ObservationOutbox, отчёт и клиентский CSV не содержат `respondent_key`, инициалов и строк (0.15, 1.4b, 1.16, 1.27b, 1.30b, 1.32). Цена: S сверх плана 11.10 (одна колонка, один класс выдачи, один эндпоинт, экспорт).
