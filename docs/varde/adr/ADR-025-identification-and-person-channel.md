# ADR-025: Идентификация — режим выбирается перед стартом опросника; классы выдачи `aggregate` и `rows`

Статус: Proposed (delta 12.10, автор Fable; на одобрение Astra и чистой сессии Fable). Решения Oleksandr внесены: 12.10 — опросник по безопасности идентифицирован, ответы по человеку видят только трое сотрудников Vardahei IT; 13.10 — анонимность выбирается перед стартом каждого опросника, по умолчанию опросники не анонимны, в обоих режимах трое админов видят все ответы (вариант B спора 21 для всех опросников, ADR-021). Файл назван по первой редакции («person channel»); класс теперь называется `rows`.

## Контекст
План 11.10 считал анонимность свойством всей системы: Response не знает человека, любая выдача с разбивкой идёт через `privacy` с k = 3 (PRINCIPLES §6–7, ADR-021). 12.10 продукт изменился: опросник по безопасности спрашивает обязательные инициалы (F1, «2 første og 3 siste»), дашборд показывает строку на человека (инициалы, snittscore, зона, зона в раунде 1 по паре «фирма + инициалы»), а респондентам обещано: «Svara per person ser berre Vardahei IT. Bedrifta får eit samla bilete utan initialar.» KI-опросник остался анонимным и на проде обещает анонимность без оговорок; два опросника не смешиваются. Порог `minGruppe = 3` в дашборде скрывает малые роли в обоих опросниках, а свободный текст KI показывается админам по строкам. 13.10 Oleksandr решил: режим выбирается перед стартом каждого опросника, по умолчанию опросники не анонимны; анонимный режим защищает от клиента и внешних каналов, не от трёх админов.

## Решение
- **Режим идентификации живёт в `TemplateVersion.identification: initials | none`** (по умолчанию `initials`), выбирается при публикации версии — до открытия любого раунда — и публикуется вместе с версией (неизменяем). При `initials` ровно один вопрос версии помечен структурным полем `identifier: true` (тип `text`, одна строка, ≤ 8 символов); при `none` такого вопроса нет — схема (1.1) отклоняет оба нарушения. `Round.identification` копируется из версии при открытии первого RoundClient и дальше не меняется (как `template_version`, ADR-022); сменить режим — значит опубликовать новую версию и открыть новый раунд. Шаблон по безопасности — `initials`, KI-шаблон — `none`; у каждого опросника свой шаблон, режимы не смешиваются.
- **`Response.respondent_key`** — отдельная колонка (нормализованные инициалы: trim, верхний регистр, ≤ 8 символов), заполняется только серверным normalizer (`rules/runner`, ADR-006) из ответа на identifier-вопрос; в `answers` этого ответа нет никогда (тест). В анонимных раундах `respondent_key` всегда null; присланное поле identifier отклоняется; ограничение БД проверяет, что non-null бывает только в раундах с `identification = initials`. В идентифицированном раунде обе части одного человека — common и leader — несут один и тот же `respondent_key` (runner берёт его из черновика и шлёт с обеими отправками; leader-отправка без него → 400): иначе удаление по человеку (ADR-017) не охватит часть руководителя. Это атрибут человека, а не ключ связи отправок: FK и общего `submission`-ключа между частями по-прежнему нет (ADR-006, ADR-024), класс `rows` показывает только общую часть, канал leader — только часть руководителя (ADR-021); в анонимных раундах обе части без ключа. Никаких Contact, Registration, ProgressEvent, IP; время — день; ProgressEvent остаётся анонимным по сессии. Связь между раундами по человеку — пара `(client, respondent_key)` между идентифицированными раундами одного семейства якорей; связь приблизительная (однофамильцы по инициалам, опечатки) и так и называется в UI, как сейчас («same initialar i same bedrift»).
- **Два класса выдачи в `privacy`.** `aggregate` — всё, что было: k = 3 на группу, подавление дополнительных групп, история выдач в `privacy.release()`; применяется в обоих режимах и это единственное, что уходит клиенту и во внешние каналы (клиентский CSV, отчёт, Atlas, ассистент). Порог в идентифицированных раундах не снимается (предложение ENDRINGAR п. 1 «k только для анонимных» не принято): агрегатные виды — то, что уходит клиенту, и это паритет с `minGruppe`. `rows` — строки общей части для трёх админов в обоих режимах: только админ-сессия, по одному клиенту или по всем, каждое чтение в AuditLog (кто, объём, когда) в одной транзакции с ответом. В идентифицированных раундах строка несёт `respondent_key`, и на классе `rows` стоят вид по сотруднику «Svar per tilsett» (snittscore, зона, зона предыдущего идентифицированного раунда), сравнение по людям и экспорт Master_Analyse (1.30b); в анонимных раундах строки без ключа (роль, ответы, свободный текст — как цитаты в старом KI-дашборде), связи между раундами нет, а вид по сотруднику, сравнение по людям и экспорт Master_Analyse отвечают 404. Класс `rows` никогда не попадает в снимки, контекст ассистента, Proposal, ObservationOutbox, автоматический отчёт и клиентский CSV — ни `respondent_key`, ни инициалы, ни строки.
- **Кто что видит.** Трое админов — `aggregate` + `rows` + leader-эндпоинт (ADR-021) в обоих режимах; клиент — «samla bilete utan initialar»: агрегаты под k по клиенту, вопросам и зонам, выводы, сравнение с прошлым раундом, отчёт 5.1 — без инициалов, без строк и без части руководителя; ассистент, Atlas, CSV для клиента — только released-агрегаты. Анонимный режим меняет только одно: нет identifier-вопроса, `respondent_key` и всего, что на нём держится; админы и в нём видят строки.
- **Граница доверия** — вариант B для всех раундов (ADR-021, решения 12–13.10): трое админов доверены под AuditLog, живые агрегаты с порогом, класс `rows`; отдельного raw-экспорта нет. Один модуль `privacy`, режим выбирается по `Round.identification`.
- **Сравнение по людям** считается из raw (Response) только в классе `rows`; в снимках его нет. Полнота снимков (ADR-020, тест 1.11) относится к `aggregate`: после удаления raw агрегаты, FUNN и сравнение по клиентам и вопросам считаются из снимков; класс `rows` при этом пустеет — это ожидаемо и проверяется тестом, не считается потерей.
- **Хранение и удаление** — ADR-017: бессрочно, удаление только по явному запросу (по клиенту, по человеку — обе части, или по строкам, найденным админом в классе `rows` или leader-эндпоинте) под AuditLog; возврат данных клиенту по его требованию — через тот же класс `rows`; журнал удалений не даёт удалённому вернуться через restore, импорт и rollback.
- **Уведомление респондентам (0.18)** называет по режиму: идентифицированный — инициалы, кто видит ответы по человеку (трое сотрудников Vardahei IT), что клиент получает сводку без инициалов, критерий хранения и право клиента требовать возврата или удаления данных (ADR-017); анонимный — «Vardahei IT ser svara, men ikkje kven som svarte; bedrifta får eit samla bilete» — честнее сегодняшнего «er anonymt» KI-опросника на проде, текущий раунд не трогаем, это вход для 0.18; часть руководителя — «ikkje anonymt» (ADR-021).

## Альтернативы
Признак на Round, не на версии (отклонено: identifier-вопрос и текст обещания — часть шаблона; разные режимы одного шаблона ломают сравнение по людям). Хэш вместо инициалов в `respondent_key` (отклонено: дашборд и Excel шефа показывают инициалы; хэш скрывал бы их только от тех, кто уже видит строки). Связь через Contact (отклонено: Contact — персональные данные семинаров с согласием, инициалы — не контакт). `k` только для анонимных раундов (отклонено, см. выше). Раздельный `privacy` на режим (отклонено: два кода выдачи — две поверхности обхода). Класс строк только для идентифицированных раундов, анонимные строки админам недоступны (редакция итераций 1–2; снято решением 13.10).

## Последствия
PRINCIPLES §6–7 и ARCHITECTURE §4–5 переписаны; ADR-021 — вариант B для всех раундов и правило leader. Тесты: identifier не попадает в `answers`; `respondent_key` null в анонимном раунде и отклонение присланного identifier; класс `rows` → 401 без админ-сессии, AuditLog в одной транзакции, в анонимном раунде строки без `respondent_key`, вид по сотруднику и экспорт Master_Analyse → 404; контекст ассистента, ObservationOutbox, отчёт и клиентский CSV не содержат `respondent_key`, инициалов и строк (0.15, 1.4b, 1.16, 1.27b, 1.30, 1.30b, 1.32). Цена: S сверх плана 11.10 (одна колонка, один класс выдачи, один эндпоинт, экспорт).
