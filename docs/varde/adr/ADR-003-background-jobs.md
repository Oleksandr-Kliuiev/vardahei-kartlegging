# ADR-003: Фоновые задачи — pg-boss с ограничениями

Статус: Accepted (раунд 1, дополнение Astra принято)

## Контекст
Модульный монолит без Redis; AI-задачи и длинные операции (пакет семинара, импорт, отправка в Atlas) идут через pg-boss в той же базе. Без ограничений очередь съест бюджет соединений Postgres и станет вторым хранилищем ответов.

## Решение
- Один контейнер; pg-boss в базе `varde` под той же ролью `varde_app`.
- На каждый тип задачи: concurrency, timeout, предел повторов с backoff, idempotency key (например, `proposal:<input_hash>`).
- Общий бюджет соединений: пул Prisma + pg-boss ≤ лимита роли; лимит задаётся в конфигурации и проверяется тестом.
- Payload содержит только идентификаторы и hash; данные читаются из базы во время выполнения. Ответы респондентов в payload не попадают.
- Результат длинной задачи — запись (Proposal, ImportManifest) и SSE-уведомление «изменилось».

## Альтернативы
Отдельный worker-контейнер (лишний деплой при текущем объёме); BullMQ + Redis (ещё один сервис на перегруженном VPS).

## Последствия
Задача, упавшая по timeout, повторяется ограниченно и видна в админке; при переполнении очереди приём ответов не страдает (отправка ответа не проходит через очередь).
