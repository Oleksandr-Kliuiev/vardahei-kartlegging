# ADR-020: Контракт измерения — MetricDefinition и AggregateSnapshot

Статус: Accepted (новое решение Astra принято). Изменено delta 12.10: метрики зон (ADR-026); перечень правил FUNN по fixture вместо «21 правила»; раунд 1 (Forms) импортируется как идентифицированный раунд с Response (ADR-024), F-якоря `comparable` с пояснением; метрики 11.10 для расхождений «когда-либо / за последний год» сняты.

## Контекст
Fable предлагал сравнивать раунды по `anchor_key`. `kartlegging/private/dashboard.html::samanlikning()` уже предупреждает: «когда-либо» (Forms) и «за последний год» (kartlegging) несопоставимы напрямую, «Delvis» считался как «то же пароль». Один ключ не фиксирует эти различия.

## Решение
- `MetricDefinition` (versioned): key, какие вопросы/якоря и варианты входят, шкала, период воспоминания, правило знаменателя (кто считается «ответившим»), mapping вариантов, для метрик зон — пороги (ADR-026), степень сопоставимости с другими версиями (`comparable`, `approximate`, `incomparable`) с текстовым пояснением.
- `AggregateSnapshot`: на RoundClient (и «все клиенты») × версию метрики: numerator, denominator, missing, suppressed-флаг, версии метрики и правил, computed_at. Lifecycle: `computed` (пересчитываемый, пока раунд открыт) → `released` (неизменяем, триггер отклоняет UPDATE; создаётся при закрытии раунда, по суточному расписанию в варианте A спора 21, или явным действием человека) → `superseded` (при выпуске нового released того же раунда с пометкой причины; старый не удаляется). Отчёты, Atlas, ассистент и тренды читают только `released`.
- Полнота: набор MetricDefinition покрывает все распределения по вопросам × RoundClient × роль (с подавлением), метрики зон `mean_score`, `critical_share`, `zone`, `persons_per_zone` (ADR-026) и все метрики для правил FUNN канала `aggregate` из fixture-перечня (ADR-026), включая кросс-вопросную K7×K8. У каждой MetricDefinition явный вход `part: common | leader`. Метрики с `part = leader` допускаются только с population `leaders_all` (правило ниже); схема отклоняет leader-метрику с другой population, кросс-метрику common × leader и любую метрику, смешивающую части. Правила канала `leader`, включая кросс-правило F12×B13 (вход по одному клиенту), — не метрики снимков: считаются в leader-эндпоинте. Тест полноты (1.11): удалить raw в тестовой базе → дашборд (класс `aggregate`), FUNN и сравнение по клиентам и вопросам из снимков идентичны расчёту по raw; канал `person` (ADR-025) из снимков не восстанавливается — ожидаемо и проверяется тем же тестом.
- `FindingRule` versioned; `Finding` — вычисленный результат по snapshot, рабочий статус («в работе», «закрыт») — отдельная запись.
- Populations снимков: `round_client` и `all_clients` — только `part = common`. **`leaders_all` — единственная population с `part = leader`** (исключение, уточнено delta 12.10): распределения по вопросам части руководителя по всем клиентам раунда вместе, под тем же k и через тот же `privacy.release()`. Разрешено только это: ячейки «все клиенты раунда» без разбивки по клиенту и роли. Запрещено: ячейки по одному клиенту, кросс-метрики common × leader (в том числе F12×B13), любые правила канала `leader` как метрики. Читает `leaders_all` только админ-дашборд при фильтре «alle» (паритет 1.27, «X av Y leiarar»); отчёт клиенту, ObservationOutbox/Atlas, контекст ассистента и клиентский CSV её не читают — отрицательные тесты 1.32. По одному клиенту ответы руководителя и правила канала `leader` идут через leader-эндпоинт, не через снимки.
- Раунд 1 (Forms, `runde1.js`) импортируется как идентифицированный раунд `external_import` с Response (ADR-024). Метрики по F-якорям между раундом 1 и Varde — `comparable`, с пояснением в определении: вопросы и варианты дословные (решение 1 от 12.10), сопоставление вариантов по `tools/runde1_fra_excel.py` («Skjelden» → `sjeldan`), свободные варианты F15 и F20–F22 в раунде 1 не импортированы и не оценены (`docs/sonemodell.md`), раунд 1 шёл на нюношке с ошибками правописания, в раунде 2 есть en и, при включённом переключателе, nb (ADR-019). Сравнение с раундом 1 показывает только клиентов, ответивших в текущем раунде (ADR-026).
- Определения — этап 0 (0.16: метрики зон и кросс-метрики), реализация — этап 1.

## Альтернативы
Только `anchor_key` (скрывает несопоставимость); пересчёт из raw на лету (невозможен после удаления raw, невоспроизводим).

## Последствия
Тренды переживают удаление raw; сравнение показывается с оговоркой из `comparability`. Цена: включена в этап 1 (L).
