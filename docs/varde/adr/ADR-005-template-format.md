# ADR-005: Формат шаблона — ограниченный JsonLogic плюс явные структурные поля

Статус: Accepted (позиция Fable изменена по возражению Astra). Изменено delta 12.10: добавлены структурные поля `identifier`, `frozen`, `option.score` и `score_scale`, `scenario`; `tips` версии может быть пустым (ADR-025, ADR-026).

## Контекст
Fable предлагал кодировать условия показа и правила советов в JsonLogic целиком. В `kartlegging/public/sporsmal.js` зависимости вариантов — три разных механизма: `valFraa: "K3"` (варианты берутся из ответа на другой вопрос), `rutine()` исключает вариант `ingen`, `praktisk()` управляет показом отдельных вариантов; `index.html::valAv()` их соединяет. Выражать это одним предикатом неудобно, а zod не проверяет согласованность ссылок между вопросами.

## Решение
- JSON по zod-схеме в `packages/schema`; тексты в `{nn, en, nb?}` — обязательный набор задаёт `required_languages` версии (ADR-019, изменено delta 12.10: клиентские опросы — `nn` и `en`, `nb` по переключателю; семинарные — `nn`); версия неизменяема после публикации.
- Предикаты (`visible_if`, условия советов, условия правил выводов) — JsonLogic с whitelist операторов (`==`, `!=`, `in`, `and`, `or`, `!`, `>`, `>=`, `<`, `<=`, `var`, `some`, `count`), пределом глубины и запретом неизвестных ссылок.
- Структурные зависимости — явные поля вопроса: `choices_from: <question_id>`, `option.visible_if`, `exclusive_options: [...]`, `max_choices`.
- Изменено delta 12.10 — ещё структурные поля, не выражения: `identifier: true` ровно на одном вопросе версии с `identification = initials` (ADR-025); `frozen: true` на якорных вопросах, зафиксированных решением шефа (F1–F22): ассистент их не редактирует и не предлагает правок; чек-лист PRINCIPLES §3, автопроверки черновика и перевода (ARCHITECTURE §6, ADR-018) и eval (ADR-010) не применяют к ним лимит ≤25 слов и стоп-список продуктов — F20 длиннее 25 слов, F17 называет OneDrive/SharePoint, и это решение шефа; проверяется только дословность исходника (hash якоря) и принятие перевода; правка замороженного вопроса в новой версии объявляется человеком как `orthographic` (anchor_key сохраняется, переводы сбрасываются по `source_hash`, как 12.10 с исправленным нюношком) или `semantic` (новый `anchor_key`, сравнение по старому якорю прерывается) — выбор записывается в версию и в AuditLog; `option.score ∈ {0,1,2,3}` и `score_scale` версии (ADR-026); `scenario: true` с `explanation` на языках версии на вопросе-сценарии (только KI); список советов `tips` версии может быть пустым (опросник по безопасности с 12.10 без советов и сценариев).
- Единый серверный normalizer (`rules/runner`): пустой ответ, пустой массив и «не показан» нормализуются до оценки предикатов; truthiness JsonLogic не используется напрямую; ответ на identifier-вопрос переносится в `Response.respondent_key` и не остаётся в `answers` (ADR-025).
- Отдельный валидатор согласованности: ссылки на существующие вопросы, отсутствие циклов, `choices_from` только на multi-вопрос раньше по порядку.

## Альтернативы
Полный JsonLogic (громоздко, непроверяемо); свой DSL (ещё один язык, который должен писать ассистент); JS в песочнице (небезопасно, нечитаемо редактором).

## Последствия
Редактор предлагает условия из ограниченного набора; ассистент генерирует только whitelist-операторы и явные поля; сервер и runner используют один и тот же код оценки из `packages/rules`. Цена: M (валидатор, normalizer, табличные тесты).
