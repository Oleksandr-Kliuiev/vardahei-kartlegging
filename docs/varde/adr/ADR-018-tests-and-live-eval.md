# ADR-018: Тесты — инварианты плюс живой eval по триггеру, не ночной

Статус: Accepted (позиция Fable изменена по возражению Astra)

## Контекст
Fable: юнит-тесты движка, интеграционные на Postgres, Playwright, записанные fixtures ассистента в CI и ночной прогон на живой модели. Astra: записанные ответы проверяют приложение, а не качество модели; ночной прогон при таком объёме не нужен; не хватает тестов инвариантов.

## Решение
- Базовый набор без изменений: табличные тесты `packages/rules`; интеграционные API на Postgres в контейнере; Playwright для runner и admin.
- Тесты инвариантов (обязательны в каждом этапе): попытка выдачи в обход `privacy` (lint-правило + тест), таблица утечек (итог + видимая роль, малые клиенты, экспорт, timestamps), replay отправки и потеря HTTP-ответа после commit, миграции вперёд/назад на fixture-базе, семантика ветвления (пустые значения, `choices_from`, `exclusive_options`), повторный импорт без дублей.
- Ассистент: золотой набор из 10 брифов на записанных ответах в CI; живой прогон запускается командой и обязателен (а) перед сменой любого из трёх: hash промпта, deployment/версии модели, версии набора брифов — отчёт eval в репозитории привязан к тройке `(prompt_hash, deployment, briefs_version)`, и CI валится, если текущая тройка не имеет отчёта с pass, (б) перед приёмкой этапа, где менялся `assistant`. Ночного прогона нет; deployment закреплён на версии модели.
- Context-budget тест: файл source/test/e2e/css > 700 строк валит CI.

## Альтернативы
Ночной живой прогон (стоимость и шум без пользы при закреплённой версии модели).

## Последствия
Смена модели — осознанное событие с отчётом. Цена: M (инварианты).
