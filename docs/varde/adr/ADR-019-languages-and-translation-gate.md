# ADR-019: Три языка; публикация блокируется до принятия всех требуемых переводов

Статус: Accepted (решение Oleksandr; механизм согласован; уточнение U1 подтверждено Astra в раунде 2)

## Контекст
Букмол — третий язык с первого дня (решение Oleksandr). Вопрос: блокировать публикацию до обновления всех переводов или публиковать с пометкой «перевод устарел». Astra: блокировать; следствие — букмол обоих текущих опросов нужен в этапе 1, до замены kartlegging.

## Решение
- Тексты в `{nn, nb, en}`; нюношк — исходный язык; у клиента язык по умолчанию, респондент переключает.
- Для каждого языка версии хранится `translation_acceptance = {source_hash, accepted_by, at}`. Изменение смысла, вариантов или пояснений вопроса меняет `source_hash` и сбрасывает принятие соответствующих переводов.
- Публикация возможна только когда все **требуемые** языки приняты для текущего `source_hash`. Действующая опубликованная версия продолжает работать целиком.
- `required_languages` задаётся на шаблоне и **фиксируется в опубликованной версии** вместе с остальным содержимым; изменение набора на шаблоне действует только на следующую версию. По `audience` шаблона: `client_survey` — всегда `nn, nb, en`, схема отклоняет меньший набор (тест в 1.5); `seminar_live` и `seminar_after` могут объявить только `nn`. Админка — только нюношк. (Уточнение U1, подтверждено Astra.)
- Этап 1: букмол обоих текущих опросов делается вне платформы (любым инструментом), проверяется носителем и импортируется с принятием. Этап 2: перевод как умение ассистента → Proposal → принятие носителем.
- Автопроверки ассистента говорят «все требуемые языки», не «оба языка»; проверка форм nn/nb — дешёвый первый фильтр.

## Альтернативы
Публикация с пометкой «устарел» (респондент видит смесь версий; невозможно сравнивать ответы).

## Последствия
Этап 1 получает задачу перевода и носителя-ревьюера (вопрос 4 к Oleksandr). Тест: «устаревший перевод блокирует publish».
