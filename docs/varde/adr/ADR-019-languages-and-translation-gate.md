# ADR-019: Языки — нюношк и английский обязательны для клиентских опросов, букмол включается переключателем версии; публикация блокируется до принятия всех требуемых переводов

Статус: Accepted (решение Oleksandr; механизм согласован; уточнение U1 подтверждено Astra в раунде 2). Изменено delta 12.10: решение 11.10 «букмол третьим языком с первого дня» заменено решением 12.10 «букмол — отдельным переключателем, не обязателен для каждого опроса»; `en` для `client_survey` остаётся обязательным, как 11.10; задача 1.3 и носитель букмола — только при включённом переключателе; перевод замороженного якоря не меняет `anchor_key`.

## Контекст
11.10 букмол был третьим языком с первого дня; 12.10 Oleksandr заменил это переключателем: букмол включается отдельно для опроса, где он нужен, носитель букмола нужен только там. Вопрос механизма остался прежним: блокировать публикацию до обновления всех переводов или публиковать с пометкой «перевод устарел». Astra: блокировать. Оба текущих опроса kartlegging идут на nn и en.

## Решение
- Тексты в `{nn, en, nb?}` для клиентских опросов, `{nn}` достаточно для семинарных; нюношк — исходный язык; у клиента язык по умолчанию (из языков версии, иначе nn); респондент переключает между языками версии, невключённый язык не показывается. Схема текстов в ADR-005 согласована с этим набором.
- Для каждого языка версии хранится `translation_acceptance = {source_hash, accepted_by, at}`. Изменение смысла, вариантов или пояснений вопроса меняет `source_hash` и сбрасывает принятие соответствующих переводов.
- Публикация возможна только когда все **требуемые** языки приняты для текущего `source_hash`. Действующая опубликованная версия продолжает работать целиком.
- `required_languages` задаётся на шаблоне и **фиксируется в опубликованной версии** вместе с остальным содержимым; изменение набора на шаблоне действует только на следующую версию. Переключатель букмола — это включение `nb` в `required_languages` шаблона: включённый язык должен быть принят до публикации следующей версии, невключённый респонденту не показывается. По `audience` шаблона: `client_survey` — `nn` и `en` обязательны (как 11.10), `nb` по переключателю; схема отклоняет клиентский набор без `nn` или без `en` (тест в 1.5); `seminar_live` и `seminar_after` могут объявить только `nn`. Админка — только нюношк. (Уточнение U1, подтверждено Astra; набор для `client_survey` изменён delta 12.10.)
- Этап 1: оба текущих опроса публикуются с `nn, en`, как в kartlegging, переключатель букмола выключен; cutover от букмола не зависит. Когда Oleksandr включает переключатель для шаблона, выполняется 1.3: текст вне платформы (любым инструментом), проверка носителем, импорт с принятием, новая версия. Этап 2: перевод как умение ассистента → Proposal → принятие носителем — для включённых языков.
- Перевод замороженного якоря (ADR-005, `frozen`) не меняет `anchor_key`: вопрос тот же, язык показа другой. Язык ответа хранится в `Response.lang`; то, что раунд 1 шёл только на нюношке, а позже часть респондентов отвечает на en или nb, записывается в текст `comparability` метрик (ADR-020), не ломает сопоставимость.
- Автопроверки ассистента говорят «все требуемые языки», не «оба языка»; проверка форм nn/nb — дешёвый первый фильтр.

## Альтернативы
Публикация с пометкой «устарел» (респондент видит смесь версий; невозможно сравнивать ответы).

## Последствия
Носитель букмола нужен только при включённом переключателе. Тесты: «устаревший перевод включённого языка блокирует publish»; «клиентский шаблон с `nn, en` без `nb` публикуется»; «клиентский шаблон без `nn` или без `en` отклонён».
