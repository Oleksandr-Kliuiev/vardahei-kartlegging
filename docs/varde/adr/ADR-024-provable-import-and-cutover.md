# ADR-024: Доказуемый импорт и переключение с kartlegging

Статус: Accepted (новое решение Astra принято; дополнено в раунде 2 по B9, B10, B13). Изменено delta 12.10: раунд 1 (Forms) импортируется как идентифицированный раунд с Response, а не как снимки; `F1` → `respondent_key`; срок архива `svar.jsonl` — только «после отчёта, не позднее 90 дней после cutover»; итерация 3 — `source_id` = постоянный `id` строки `svar.jsonl` (для раунда 1 — ключ записи), а не hash содержимого: identity переживает очистку при rollback.

## Контекст
На 11.10 `kartlegging/private/runde1.js` содержал только агрегаты Forms; с 12.10 он содержит 57 ответов раунда 1 по людям с инициалами, без свободного текста и без части руководителя (формат — `tools/runde1_fra_excel.py`), и дашборд сравнивает раунды по фирмам, вопросам и людям. Строка `svar.jsonl` содержит и общую часть, и часть руководителя (`leiardel`) вместе, а в опроснике по безопасности — инициалы в `svar.F1`; старый сервер доверяет присланной строке `versjon`.

## Импорт
- `ImportManifest`: источник, hash файла, число строк, принятых, отклонённых с причинами, статус, кто запустил, итоговая сверка.
- Строка `svar.jsonl` → common Response с `source_id = id` строки — UUID, который kartlegging присваивает при приёме (`docs/kartlegging-teknisk.md`, `server.js::randomUUID`); identity строки не зависит от её содержимого и потому переживает очистку части руководителя при rollback; hash строки и файла — только контроль целостности в ImportManifest; строка без `id` или с повторяющимся `id` → rejected с причиной (изменено delta 12.10, итерация 3: раньше `source_id = hash(строки)`). Для опросника по безопасности `svar.F1` нормализуется в `respondent_key` и в `answers` не попадает (ADR-025), `versjon` строки сопоставляется с TemplateVersion по дате; если `leiardel = true` — дополнительно leader Response **без** `source_id` и без общего submission-ключа с common (в опроснике по безопасности — с тем же `respondent_key`); обе создаются в одной транзакции. У каждой части свой `content_hash` (ADR-006); для импортированной leader-части он считается из части `leiardel` строки той же нормализацией, что и при живой отправке, — это ключ сопоставления для журнала удалений при rollback (шаг 5), без хранимой связи с common. Повторный импорт пропускает строки, чей `id` уже есть у common Response (`existing`) **или в журнале удалений** (`suppressed`; `DeletionLedger`, ADR-017): удалённое по запросу импортом не возвращается, а leader не дублируется, потому что создаётся только вместе с common; строка, у которой при rollback вырезана часть руководителя, сохраняет `id` и узнаётся как `existing` — ни common, ни leader для неё не создаются.
- Сверка по счётчикам отдельно: строк источника = `accepted` + `rejected` + `existing` + `suppressed`; common Response; leader Response; расхождение → manifest `failed`, транзакция откатывается.
- Историческая связь частей существует в исходном файле; в базе Varde её нет. После удаления архива (`svar.jsonl` и `runde1.js`, задача 1.36) связь восстановить нельзя.
- TemplateVersion для импорта восстанавливается из `sporsmal.js` соответствующей версии (git-история kartlegging или «текст на дату экспорта» с пометкой в manifest).
- Раунд 1 (Forms, `runde1.js`) → Round типа `external_import` с `identification = initials` на восстановленной TemplateVersion опросника по безопасности (те же id вопросов F2–F19 и вариантов — сопоставление `SP`/`SVAR` из `runde1_fra_excel.py`; F15 как multi; F1 → identifier; F20–F22 без ответов): каждая запись → common Response с `source_id = sha256("runde1|" + k + "|" + init)` — ключ записи, по которому `runde1_fra_excel.py` её и собирает (`folk[(k, ini)]`; запись при очистке только удаляется целиком, поэтому ключ стабилен) и `respondent_key` из `init`; записи, чей `source_id` есть в журнале удалений, пропускаются как `suppressed`, уже импортированные — `existing`; leader Response нет (Forms не имел части руководителя); ImportManifest с hash `runde1.js` как контролем целостности. Сверка: записей источника = `accepted` + `existing` + `suppressed`, leader = 0; counts по клиентам, snittscore, kritisk andel и `persons_per_zone` раунда 1 равны расчёту старого дашборда на источнике без записей из журнала (при пустом журнале — старому дашборду как есть; fixture-процедура паритета вычитает записи журнала и перечисляет их в evidence числом); повторный импорт — 0 новых строк. Метрики `comparable` с пояснением (ADR-020). Fixtures для тестов — синтетические (выдуманные инициалы, тот же формат); сверка с настоящим файлом — только числами в evidence, без инициалов. Снимки раунда 1 создаются тем же `privacy.release()`.
- Паритет проверяется на согласованных fixtures с перечнем намеренных исправлений.

## Репетиция (1.34)
В staging: свежий импорт, сверка, DNS-план, rollback выполнен один раз, отчёт. Полный цикл идентичности (итерация 3): удаление по запросу трёх видов (`respondent` в идентифицированном раунде, только leader-часть и только common-часть в анонимном раунде) → rollback с очисткой архива по журналу → повторный cutover с повторным импортом: 0 новых строк, вырезанная часть руководителя не воссоздана, удалённые строки `suppressed`, остальные `existing`, счётчики сходятся, снимки не меняются.

## Production cutover (1.35)
1. Oleksandr закрывает текущую кампанию в kartlegging (все RoundClient «stengd»); запись в `hendingar.jsonl`.
2. Финальный импорт `svar.jsonl` с manifest; сверка счётчиков (с `suppressed`) и counts по клиентам против старого дашборда за вычетом записей журнала удалений.
3. Go/no-go: чек-лист (сверка, тесты инвариантов 1a–1c зелёные на artifact hash, бэкап снят) с подписью Oleksandr в `stages/stage-1/cutover.md`.
4. DNS `kartlegging.vardahei.tech` → Varde. В той же процедуре `svar.jsonl` и `private/runde1.js` выносятся из старого приложения в зашифрованный архив (age, ключ оператора, вне VPS); kartlegging остаётся только как redirect, не хранит raw и не отдаёт `/runde1.js` (изменено delta 12.10: `runde1.js` — тоже raw с инициалами).
5. Rollback (до 7 дней): DNS назад; оператор восстанавливает оба файла архива в kartlegging (действие в AuditLog Varde) и применяет журнал удалений (список выдаёт Varde; изменено delta 12.10): из `svar.jsonl` удаляются строки, чей `id` есть в журнале как `source_id`, из `runde1.js` — записи, чей ключ `(k, init)` даёт `source_id` из журнала (строка или запись целиком, вместе с частью руководителя); у строк `svar.jsonl`, для которых hash части `leiardel` (та же нормализация, что при импорте) совпадает с `content_hash` leader-tombstone того же клиента и раунда, часть руководителя вырезается (`leiardel = false`, B-ответы удалены), а `id` строки не меняется — повторный импорт узнаёт её как `existing`; совпадение у двух руководителей с одинаковыми ответами вырезает обе — допустимая ошибка в сторону удаления в копии для rollback. При повторном cutover архивирует снова; повторный импорт применяет журнал сам. Ответы, принятые Varde после переключения, остаются в базе Varde и помечаются `accepted_during_cutover`; при повторном переключении они не импортируются заново и не теряются; kartlegging при rollback открывает приём только для раундов, явно переоткрытых Oleksandr.
6. Архив удаляется после отчёта клиентам, но не позднее 90 дней после cutover независимо от готовности отчёта (задача 1.36); raw в Varde хранится бессрочно (ADR-017), поэтому третьего срока нет.

## Альтернативы
Ручной перенос; раунд 1 только как снимки без Response (план 11.10; снято delta 12.10: сравнение по людям и экспорт для шефа требуют строк); общий ключ между частями ответа; `source_id = hash(строки)` (редакция до итерации 3: очистка части руководителя при rollback меняет hash → дубль или срыв сверки при повторном импорте); откладывать удаление до закрытия окна rollback (отклонено: право на удаление исполняется сразу, а окон rollback может быть несколько).

## Последствия
Тесты: «повторный импорт без дублей (common и leader)», «counts совпадают по счётчикам, включая `existing` и `suppressed`», «строка из журнала удалений при импорте не восстанавливается», «полный цикл удаление → rollback с очисткой → повторный cutover: 0 новых строк, вырезанная часть не воссоздана», «строка без `id` → rejected», «rollback не теряет ответы Varde и не возвращает удалённое», «удалённая часть руководителя анонимного раунда после rollback вырезана из своей строки», «удалённая запись раунда 1 после rollback отсутствует в `runde1.js`». Цена: checkpoints 1a и 1c.
