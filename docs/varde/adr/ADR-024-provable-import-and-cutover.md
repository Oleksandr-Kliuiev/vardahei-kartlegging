# ADR-024: Доказуемый импорт и переключение с kartlegging

Статус: Accepted (новое решение Astra принято; дополнено в раунде 2 по B9, B10, B13). Изменено delta 12.10: раунд 1 (Forms) импортируется как идентифицированный раунд с Response, а не как снимки; `F1` → `respondent_key`; срок архива `svar.jsonl` — только «после отчёта, не позднее 90 дней после cutover».

## Контекст
На 11.10 `kartlegging/private/runde1.js` содержал только агрегаты Forms; с 12.10 он содержит 57 ответов раунда 1 по людям с инициалами, без свободного текста и без части руководителя (формат — `tools/runde1_fra_excel.py`), и дашборд сравнивает раунды по фирмам, вопросам и людям. Строка `svar.jsonl` содержит и общую часть, и часть руководителя (`leiardel`) вместе, а в опроснике по безопасности — инициалы в `svar.F1`; старый сервер доверяет присланной строке `versjon`.

## Импорт
- `ImportManifest`: источник, hash файла, число строк, принятых, отклонённых с причинами, статус, кто запустил, итоговая сверка.
- Строка `svar.jsonl` → common Response с `source_id = hash(строки)`; для опросника по безопасности `svar.F1` нормализуется в `respondent_key` и в `answers` не попадает (ADR-025), `versjon` строки сопоставляется с TemplateVersion по дате; если `leiardel = true` — дополнительно leader Response **без** `source_id`, без `respondent_key` и без общего ключа с common; обе создаются в одной транзакции. Повторный импорт пропускает строки, чей hash уже есть у common Response, — leader не дублируется, потому что создаётся только вместе с common.
- Сверка по трём счётчикам отдельно: строк источника, common Response, leader Response; расхождение → manifest `failed`, транзакция откатывается.
- Историческая связь частей существует в исходном файле; в базе Varde её нет. После удаления архива `svar.jsonl` (задача 1.36) связь восстановить нельзя.
- TemplateVersion для импорта восстанавливается из `sporsmal.js` соответствующей версии (git-история kartlegging или «текст на дату экспорта» с пометкой в manifest).
- Раунд 1 (Forms, `runde1.js`) → Round типа `external_import` с `identification = initials` на восстановленной TemplateVersion опросника по безопасности (те же id вопросов F2–F19 и вариантов — сопоставление `SP`/`SVAR` из `runde1_fra_excel.py`; F15 как multi; F1 → identifier; F20–F22 без ответов): каждая запись → common Response с `source_id = hash(записи)` и `respondent_key` из `init`; leader Response нет (Forms не имел части руководителя); ImportManifest с hash `runde1.js`. Сверка: записей источника = common Response, leader = 0; counts по клиентам, snittscore, kritisk andel и `persons_per_zone` раунда 1 равны старому дашборду; повторный импорт — 0 новых строк. Метрики `comparable` с пояснением (ADR-020). Fixtures для тестов — синтетические (выдуманные инициалы, тот же формат); сверка с настоящим файлом — только числами в evidence, без инициалов. Снимки раунда 1 создаются тем же `privacy.release()`.
- Паритет проверяется на согласованных fixtures с перечнем намеренных исправлений.

## Репетиция (1.34)
В staging: свежий импорт, сверка, DNS-план, rollback выполнен один раз, отчёт.

## Production cutover (1.35)
1. Oleksandr закрывает текущую кампанию в kartlegging (все RoundClient «stengd»); запись в `hendingar.jsonl`.
2. Финальный импорт `svar.jsonl` с manifest; сверка трёх счётчиков и counts по клиентам против старого дашборда.
3. Go/no-go: чек-лист (сверка, тесты инвариантов 1a–1c зелёные на artifact hash, бэкап снят) с подписью Oleksandr в `stages/stage-1/cutover.md`.
4. DNS `kartlegging.vardahei.tech` → Varde. В той же процедуре `svar.jsonl` выносится из старого приложения в зашифрованный архив (age, ключ оператора, вне VPS); kartlegging остаётся только как redirect и не хранит raw.
5. Rollback (до 7 дней): DNS назад; оператор восстанавливает архив в kartlegging (действие в AuditLog Varde), при повторном cutover архивирует снова. Ответы, принятые Varde после переключения, остаются в базе Varde и помечаются `accepted_during_cutover`; при повторном переключении они не импортируются заново и не теряются; kartlegging при rollback открывает приём только для раундов, явно переоткрытых Oleksandr.
6. Архив удаляется после отчёта клиентам, но не позднее 90 дней после cutover независимо от готовности отчёта (задача 1.36); raw в Varde хранится бессрочно (ADR-017), поэтому третьего срока нет.

## Альтернативы
Ручной перенос; раунд 1 только как снимки без Response (план 11.10; снято delta 12.10: сравнение по людям и экспорт для шефа требуют строк); общий ключ между частями ответа.

## Последствия
Тесты: «повторный импорт без дублей (common и leader)», «counts совпадают по трём счётчикам», «rollback не теряет ответы Varde». Цена: checkpoints 1a и 1c.
