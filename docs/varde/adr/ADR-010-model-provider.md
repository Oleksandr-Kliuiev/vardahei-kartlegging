# ADR-010: Один провайдер модели за тонким адаптером

Статус: Accepted (позиция Fable изменена по возражению Astra). Изменено delta 12.10: критерии eval не применяют стоп-список и лимит слов к текстам замороженных якорей (ADR-005). **Изменено 13.10 (решение Oleksandr): провайдер — Anthropic API (Claude) вместо Azure OpenAI.**

## Контекст
Fable предлагал Azure OpenAI плюс Anthropic как второго провайдера за одним адаптером. Astra: второй провайдер требует отдельной проверки условий обработки данных и своего набора evals; один интерфейс не делает переключение безопасным. При трёх пользователях и пяти семинарах в год это неоправданная работа. 13.10 Oleksandr выбрал Anthropic API как единственного провайдера; Azure OpenAI не используется.

## Решение
- Один провайдер — первичный Anthropic API (Claude API, `POST /v1/messages`), одна организация и один workspace Vardahei, один API-ключ приложения только в env на VPS (`/etc/varde/app.env`), ни в репо, ни в CI.
- Модель по умолчанию — `claude-opus-5-5`; кандидат для сравнения в eval — `claude-sonnet-5-5` (дешевле: $2/$10 против $4/$20 за 1M токенов на 13.10). Окончательный выбор модели по отчёту eval — за Oleksandr. ID модели и `effort` фиксируются в конфиге и в каждом Proposal; ID — точные строки без суффиксов дат.
- Вызовы: структурированный вывод по JSON-схеме через `output_config.format` (или strict tool use); принудительный `tool_choice` (`any`/`tool`) у этих моделей не поддерживается — не использовать; adaptive thinking, `effort` задаётся явно; обработка `stop_reason: "refusal"` (выход не используется, Proposal получает статус ошибки); prefill ассистента не используется.
- Checkpoint 0d «AI-допуск» (ворота G0) проверяет по документам Anthropic: применимость Commercial Terms и DPA к организации Vardahei; срок хранения входов и выходов API по умолчанию и возможность zero data retention (только по договорённости с Anthropic) — со ссылкой на документ и дату; место обработки (`inference_geo`: есть ли вариант ЕС; если нет — передача в третью страну по DPA/SCC и правка записи в реестре обработки и в `docs/personvern.md`, где сейчас «Overføring til tredjeland: Nei»); кто имеет доступ к Console и ключу; лимиты расходов. G0 блокирует 2b и этап 4, но не этапы 1 и 2a.
- Выбор модели — слепой тест: 10 брифов × 2 модели × 2 прогона. Шкала носителя на каждый бриф: смысл 1–5, естественность нюношка 1–5, минуты правки до публикуемого текста; критические ошибки — текст не на запрошенном языке или смесь nn/nb, выдуманный факт или цифра, название продукта из стоп-списка, нарушение JSON-схемы, отказ модели (`refusal`). Порог pass: медиана естественности ≥ 4, медиана смысла ≥ 4, ≤ 2 брифов с правкой > 5 минут, 0 критических ошибок у ≥ 8 из 10 брифов. При pass обеих моделей отчёт показывает обе суммы и стоимость; выбирает Oleksandr. Harness остаётся в репозитории как eval fixtures. Изменено delta 12.10: критические ошибки «название продукта» и автопроверка «≤25 слов» не применяются к дословным текстам и переводам замороженных якорей (`frozen`, ADR-005) — F17 называет OneDrive/SharePoint, F20 длиннее 25 слов по решению шефа; в брифах eval таких текстов нет, а при переводе замороженного вопроса (2.10) оценивается только естественность и смысл.
- Адаптер: интерфейс «структурированный вывод по JSON-схеме, инструменты, стоимость, версия модели»; реализация одна — официальный SDK `@anthropic-ai/sdk`. Второй провайдер — только после подтверждённой потребности (порог носителей не пройден, недоступность, цена) и своего ADR с проверкой условий.
- Contingency: если ни одна модель не проходит пороги, checkpoint 0d расширяется проверкой другой модели Anthropic или одного дополнительного провайдера (свой ADR, своя проверка условий, тот же harness) до открытия ворот G0, то есть до 2b.

## Альтернативы
Azure OpenAI (выбор до 13.10; отменён решением Oleksandr); два провайдера сразу (двойная юридическая и eval-работа); без адаптера (замена провайдера становится переписыванием).

## Последствия
ID модели, `effort` и версия промпта фиксируются в каждом Proposal; смена модели — через живой eval (ADR-018). Цена изменения: S.
