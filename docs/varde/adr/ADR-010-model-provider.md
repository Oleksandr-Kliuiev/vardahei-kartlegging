# ADR-010: Один провайдер модели за тонким адаптером

Статус: Accepted (позиция Fable изменена по возражению Astra). Изменено delta 12.10: критерии eval не применяют стоп-список и лимит слов к текстам замороженных якорей (ADR-005).

## Контекст
Fable предлагал Azure OpenAI плюс Anthropic как второго провайдера за одним адаптером. Astra: второй провайдер требует отдельной проверки условий обработки данных и своего набора evals; один интерфейс не делает переключение безопасным. При трёх пользователях и пяти семинарах в год это неоправданная работа.

## Решение
- Один провайдер — Azure OpenAI, один одобренный deployment. Deployment type не `Global`; регион ЕЭЗ; `DataZone` рассматривается только после проверки его географии.
- Checkpoint 0d «AI-допуск» (ворота G0) проверяет: подписка на Vardahei; DPA; статус abuse monitoring и срок хранения промптов для конкретного API (утверждение «30 дней» не принимается без подтверждения в документации); запись в реестре обработки. G0 блокирует 2b и этап 4, но не этапы 1 и 2a.
- Выбор deployment — слепой тест: 10 брифов × 2 deployment × 2 прогона. Шкала носителя на каждый бриф: смысл 1–5, естественность нюношка 1–5, минуты правки до публикуемого текста; критические ошибки — текст не на запрошенном языке или смесь nn/nb, выдуманный факт или цифра, название продукта из стоп-списка, нарушение JSON-схемы. Порог pass: медиана естественности ≥ 4, медиана смысла ≥ 4, ≤ 2 брифов с правкой > 5 минут, 0 критических ошибок у ≥ 8 из 10 брифов. Выбирается deployment с лучшей суммой при pass; если ни один не прошёл — contingency ниже. Harness остаётся в репозитории как eval fixtures. Изменено delta 12.10: критические ошибки «название продукта» и автопроверка «≤25 слов» не применяются к дословным текстам и переводам замороженных якорей (`frozen`, ADR-005) — F17 называет OneDrive/SharePoint, F20 длиннее 25 слов по решению шефа; в брифах eval таких текстов нет, а при переводе замороженного вопроса (2.10) оценивается только естественность и смысл.
- Адаптер: интерфейс «структурированный вывод по JSON-схеме, инструменты, стоимость, версия модели»; реализация одна. Второй провайдер — только после подтверждённой потребности (Azure не проходит порог носителей, недоступность, цена) и своего ADR с проверкой условий.
- Contingency (U5, подтверждено Astra): если ни один Azure deployment не проходит пороги, checkpoint 0d расширяется проверкой одного дополнительного провайдера (свой ADR, своя проверка условий, тот же harness) до открытия ворот G0, то есть до 2b.

## Альтернативы
Два провайдера сразу (двойная юридическая и eval-работа); без адаптера (замена провайдера становится переписыванием).

## Последствия
Версия модели и промпта фиксируется в каждом Proposal; смена deployment — через живой eval (ADR-018). Цена изменения: S.
