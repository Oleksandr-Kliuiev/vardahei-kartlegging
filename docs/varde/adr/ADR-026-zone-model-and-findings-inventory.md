# ADR-026: Модель зон — `option.score` в версии шаблона, зоны как MetricDefinition, перечень правил FUNN по fixtures

Статус: Proposed (delta 12.10, автор Fable; на одобрение Astra и чистой сессии Fable). Модель зон — решение Asbjørn 12.10 (Master_Analyse), не обсуждается.

## Контекст
12.10 опросник по безопасности получил модель зон по Master_Analyse (`docs/sonemodell.md`): у каждого варианта ответа цвет 0–3 (`farge` в `sporsmal.js`, 16 оценённых вопросов из F1–F22), snittscore = среднее баллов, kritisk andel = доля ответов ≥ 2, пороги `person [1, 2, 3]` и `samla [0.5, 1.5, 2.5]` (`SONER`). То, что сотрудник не может попасть в Raud (максимум 2,25), — свойство данных, не архитектуры. Набор правил FUNN сменился: у опросника по безопасности новые правила на F-вопросах, правила по ответам руководителя и кросс-правило «люди знают, куда сообщать, а записанного плана нет» (F12 × B13); правила KI не менялись. План говорил «21 правило FUNN, включая K7×K8» по версии 11.10, JsonLogic для предикатов (ADR-005) и «сравнение с раундом 0 по трём метрикам» — всё это устарело.

## Решение
- **Баллы — структурное поле варианта**: `option.score ∈ {0, 1, 2, 3}` в TemplateVersion (ADR-005: таблица соответствий — явное поле, не выражение). Вопросы без баллов — информационные (F1, F2, F15, F20–F22). Баллы публикуются вместе с версией и неизменяемы; у замороженных якорей (ADR-005, `frozen`) меняются только решением шефа. Шкала объявляется на версии: `score_scale: "risk-0-3"` с уровнями `gron | gul | oransje | raud` и подписями на языках версии (ADR-019).
- **Зоны — версионируемые MetricDefinition (ADR-020), не часть версии шаблона и не FindingRule**: `mean_score` (среднее баллов по оценённым якорям; populations: вопрос × группа, группа = клиент | роль | все клиенты), `critical_share` (доля ответов со `score ≥ 2`), `zone` (уровень по порогам из определения метрики: `thresholds.person = [1, 2, 3]`, `thresholds.aggregate = [0.5, 1.5, 2.5]`; сравнение для person — `≥`, для aggregate — `>`, как в `sonemodell.md`), `persons_per_zone` (гистограмма людей по зоне на группу — агрегат под k). Уровень человека (`zone` по `thresholds.person`) считается только в канале `rows` (ADR-025) и в снимки не входит. Смена порогов = новая версия `zone` с `comparability` к предыдущей и текстом; `mean_score` и `critical_share` от порогов не зависят и остаются `comparable`. Смена баллов варианта = новая версия шаблона и новая версия метрик с пометкой `comparability` — таких изменений в delta нет.
- **Перечень правил FUNN фиксируется fixture-файлом**, сгенерированным из `dashboard.html` (`FUNN`, `leiarFunn`, кросс-правило, вычисляемые выводы KI) той версии kartlegging, с которой делается cutover; критерии паритета (1.28) ссылаются на этот файл, не на число. По версии `KARTLEGGING.versjon = "2026-10-12"`: опросник по безопасности — 15 правил по общей части (F3, F5–F14, F16–F19), 9 по части руководителя (B7, B9, B10, B12, B13, B17, B18 ×2, B19), 1 кросс-правило F12 × B13; KI — 8 правил по общей части (включая кросс-правило K7 × K8), 2 вычисляемых вывода (часы в неделю на рутину из K3/K4; самая тяжёлая задача из K16/K17/K18) и 4 по части руководителя (L4, L5, L8, L10). Пороги правил — данные FindingRule: `threshold` 0,15 (medium) и 0,30 (high) от знаменателя `basis`, `min_count = 2` («éin person er ein person, ikkje eit mønster»); вычисляемые выводы — метрики `routine_hours_week` и `heaviest_task` плюс правило с порогом (≥ 1 ч/неделю).
- **FindingRule получает `channel: aggregate | leader`.** `aggregate` — считается по снимкам, попадает в дашборд, отчёт, Atlas, ассистента. `leader` — правила по части руководителя и кросс-правило F12 × B13 (вход: released-агрегат F12 под k и ответ руководителя B13): считается при чтении leader-эндпоинта по одному клиенту (ADR-021, правило (a)), показывается рядом с таблицей руководителя, в снимки, отчёт, Atlas, ассистента и CSV не попадает. При фильтре «alle»: простые leader-правила (условие на один вопрос части руководителя) считаются из снимков `leaders_all` (ADR-020) как «X av Y leiarar» без имён клиентов; кросс-правило F12×B13 при «alle» считается leader-каналом по клиентам (каждое чтение в AuditLog) и показывает число клиентов без имён — намеренное отклонение паритета.
- **Сравнение с раундом 1** (1.29): по клиентам и по вопросам на `mean_score`, `critical_share`, `zone` и их изменении из released-снимков раунда 1 (ADR-024, идентифицированный импорт) и текущего раунда; раунд 1 ограничивается клиентами, ответившими в текущем раунде (решение 8), как фильтр population при расчёте, не как правка снимка; оговорка из `comparability` показывается. Сравнение по людям — канал `rows` (ADR-025).

## Альтернативы
Зоны как первые FindingRule (ENDRINGAR п. 2; отклонено: зона — измерение, правила выводов её потребляют). Баллы и пороги в JsonLogic (отклонено: таблица, не выражение; редактору и ассистенту нечего в ней генерировать). Пороги внутри TemplateVersion (отклонено: сопоставимость зон между версиями — забота контракта измерения, а не шаблона; одна модель зон должна покрывать несколько версий и раундов). Число правил в критерии приёмки (отклонено: устаревает при каждой правке дашборда).

## Последствия
`docs/sonemodell.md` остаётся человеческим описанием модели; источник истины для Varde — версия шаблона (баллы) и MetricDefinition (пороги). Задачи 0.16, 1.2, 1.10, 1.28, 1.29 переписаны; конвертер 1.2 переносит `farge` → `option.score`, `SONER` → fixture определения `zone`. Тесты: паритет snittscore, kritisk andel и зон по клиентам, ролям и вопросам на fixtures; гистограмма `persons_per_zone` под k; правила `leader` не появляются в снимках и отчёте. Цена: внутри этапа 1 (L).
