# ADR-017: Хранение и удаление по классам данных

Статус: Accepted (решения Oleksandr 12.10: ответы хранятся бессрочно; при уходе клиента остаются; удаление — только по явному запросу под AuditLog). Изменено delta 12.10: спор 17 закрыт, варианты A/B для ответов сняты; добавлен механизм удаления по запросу; остаточный риск по правовому основанию хранения связан с O5.

## Контекст
Раунд 2 brainstorm: Fable — сырые ответы 18 месяцев, Astra — 90 дней после закрытия раунда; варианты A/B и правило выбора. 12.10 Oleksandr решил: ответы обоих опросников, включая свободный текст и часть руководителя, по таймеру не удаляются; когда клиент уходит, его инициалы и ответы остаются — не удаляются и не обезличиваются. Это заменяет варианты A и B и формулировку «договор + 3 месяца» (`docs/personvern.md`). Ответы опросника по безопасности с 12.10 — персональные данные (инициалы, ADR-025), поэтому права субъекта (доступ, удаление по запросу) и решение клиента как behandlingsansvarleg по ст. 28(3)(g) этим решением не отменяются: нужен механизм удаления по явному запросу — по клиенту и по человеку. Факты раунда 2 остаются верными: набор метрик раунда фиксируется при первом release (ADR-021), поэтому хранение raw не даёт новых опубликованных разрезов по выпущенному раунду; пересчёт тех же метрик после исправления ошибки — superseded release того же набора.

## Принято
- Снимки (`AggregateSnapshot`) содержат все распределения по вопросам × RoundClient × роль (с подавлением) и все метрики, включая кросс-вопросные и метрики зон (ADR-026); агрегаты, FUNN и тренды считаются из снимков и переживают удаление raw (тест полноты 1.11 для класса `aggregate`); канал `person` (ADR-025) считается из raw и исчезает вместе с ним — ожидаемо.
- Новые метрики применяются только к раундам без release (ADR-021, правило 4); новые ретроспективные разрезы по выпущенному раунду — вне scope.
- Ответы (common и leader, закрытые и свободный текст, оба опросника, импортированные раунды) хранятся **бессрочно**. Задач удаления по таймеру и по окончании договора нет.
- **Удаление по явному запросу** (`retention.forget`): действие человека из админки с указанием основания. Область: `client` — все Response его RoundClient по обоим опросникам, обе части, свободный текст; `respondent` — `client` + `respondent_key` в идентифицированных раундах, обе части (ADR-025: leader несёт тот же ключ); `submissions` — явный список `submission_id`, найденный человеком, для строк без ключа: ответы анонимного KI-опросника, которые заявитель опознаёт по своему свободному тексту, и строки руководителя в анонимном раунде (их находит админ в leader-эндпоинте или оператор out-of-band по [O3]). Released-снимки остаются (агрегаты под k). **Журнал удалений `DeletionLedger`**: запись запроса (кто, основание, область, когда) и tombstone на каждую удалённую строку (`submission_id`, `source_id`, client, `respondent_key`, part) создаются в одной транзакции с удалением; dry-run показывает объём; повтор идемпотентен. Журнал — защита от возвращения удалённого: импорт (ADR-024) пропускает строки, чей `source_id` есть в журнале, и считает их `suppressed`; rollback cutover применяет журнал к восстановленному архиву `svar.jsonl`; restore из бэкапа (ADR-016) всегда заканчивается применением журнала, а сам журнал экспортируется отдельным зашифрованным файлом сразу после каждой записи и из старого дампа не берётся — только последний экспорт, при расхождении объединение. Обезличивание (снятие `respondent_key` с сохранением ответов) не реализуется — при необходимости отдельный ADR.
- Задачи удаления для классов со сроком (ProgressEvent, Proposal, AuditLog, Registration, Contact) — ежедневные, с dry-run, идемпотентны, повторяются после восстановления из бэкапа.
- Backup-копии: версии в SharePoint живут 35 дней; корзина SharePoint может держать удалённое ещё до 93 дней. Задача 0.10 либо подтверждает фактическое исчезновение (политика purge корзины для библиотеки бэкапов, проверено в drill), либо реестр 0.19 записывает честный эффективный максимум = 35 + 93 дня после удаления. Для удалённого по запросу это и есть срок исчезновения из всех копий.
- Часть руководителя живёт по тому же правилу, что остальные ответы; она помечена конфиденциальной и выдаётся по отдельному правилу ADR-021 [O4].
- Импортированные данные kartlegging: raw в Varde (раунд 1 из `runde1.js`, раунд 2 из `svar.jsonl`) — бессрочно, как остальные ответы; `svar.jsonl` выносится из старого приложения в зашифрованный архив в момент cutover; архив удаляется после отчёта клиентам, но не позднее 90 дней после cutover (задача 1.36) — третьего срока («не позднее удаления raw в Varde») больше нет. Исходники раунда 1 (`runde1.js` в приватном git, `Master_Analyse.xlsx` вне git) — вне Varde, владелец Oleksandr; реестр 0.19 перечисляет их как копии.
- Уведомление респондентам v2 (0.18) называет критерий хранения вместо срока: ответы хранятся, пока Vardahei IT ведёт kartlegging, и удаляются по запросу; точная формулировка на нюношке — с учётом ролей сторон [O5].

## Остаточный риск (не вопрос к Oleksandr; связан с O5)
Ст. 5(1)(e) допускает хранение в идентифицирующей форме не дольше, чем нужно для цели; цель «сравнение от раунда к раунду» у действующего клиента её покрывает, у ушедшего — слабее. Правовое основание хранения после окончания договора и условия databehandleravtale (ст. 28(3)(g): удалить или вернуть по окончании обработки) проверяет Asbjørn [O5]. Если проверка потребует удаления при уходе клиента, механизм `retention.forget` уже есть — меняются политика и текст уведомления, не архитектура.

Правило по итогам проверки [O5] (условное; решение остаётся за Oleksandr и Asbjørn):
- «databehandleravtale покрывает kartlegging av tilsette, и по окончании обработки допускается удаление, а не возврат» → ничего не меняется: `retention.forget` по клиенту выполняется по требованию клиента; обещание «svara per person ser berre Vardahei IT» остаётся.
- «клиенту положен возврат данных» → возврат строк по человеку конфликтует с этим обещанием (ADR-025). Это материальное изменение: повторный architecture gate (Astra и Fable) и решение Oleksandr между (1) возвратом только агрегатов под k (отчёт 5.1 и CSV `aggregate`) с закреплением такой формулировки в databehandleravtale и (2) изменением обещания респондентам в следующем раунде с возвратом строк по человеку. До решения возврат person-данных не реализуется; удаление по требованию клиента доступно в обоих случаях.

## История (раунд 2, снято 12.10)
Варианты A (90 дней) и B (12 месяцев) для закрытых ответов, 30/90 дней для свободного текста и правило выбора — в `astra/round-2-*.md` и `astra/final-summary.md`. Реализация обоих вариантов была одной строкой конфига retention, поэтому отказ от них ничего не меняет в цене.
