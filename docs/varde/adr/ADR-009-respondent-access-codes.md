# ADR-009: Доступ респондентов — bearer-код на RoundClient, лимиты не по IP

Статус: Accepted (дополнение Astra принято). Изменено delta 12.10: контекст о лимитах устарел, решение не меняется.

## Контекст
Код клиента в ссылке остаётся: он говорит, какой компании принадлежит ответ, а не кто ответил. На 11.10 `server.js` ограничивал отправки десятью на IP за десять минут (`forMange("svar:" + ip, 10)`); офис за одним NAT или зал семинара упирались в лимит. С 12.10 действуют лимиты `GRENSE` за 10 минут: `/api/sjekk` 300 с IP, `/api/svar` 100 с IP, `/api/framdrift` 3000 с IP и 300 на сессию, после 20 неверных кодов с IP — 429 (`docs/kartlegging-teknisk.md`); лимит по IP всё ещё общий для всего офиса, поэтому решение ниже остаётся. Коды могут попадать в логи reverse proxy.

## Решение
- Код = случайный bearer ≥128 бит (base64url, 22 символа), один на RoundClient; отзыв, перевыпуск и срок действия; старый код после перевыпуска даёт 403 с понятным текстом.
- Коды kartlegging (`server.js::lagKode()`, 10 символов ≈ 59 бит) как действующие не импортируются: в seed (1.7) хранится только их hash, чтобы старая ссылка или плакат получали страницу «avslutta», а не непонятный 403; проверяется в чек-листах 1.34/1.35.
- Лимиты отправок: на RoundClient (population_snapshot × 3 за окно раунда), на live poll (по числу вопросов × участников), глобальный; per-IP лимит остаётся только с высоким порогом против явного злоупотребления.
- Код не логируется: Caddy для runner-маршрута не пишет query string; приложение не пишет URL с кодом; в AuditLog — только hash кода.
- Именные ссылки — только для регистрации на семинар (не для ответов).

## Альтернативы
Персональные токены (точный отклик, но конец анонимности); код в URL-fragment (не попадает в логи, но хуже совместимость с QR-сканерами и текущими плакатами).

## Последствия
Тесты: отозванный код → 403; 60 отправок с одного IP в пределах квоты RoundClient проходят; образец логов не содержит кодов. Цена: M.
