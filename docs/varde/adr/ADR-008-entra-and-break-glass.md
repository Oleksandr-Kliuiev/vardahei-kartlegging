# ADR-008: Вход команды через Entra; аварийный доступ только через SSH

Статус: Accepted (позиция Fable изменена по возражению Astra)

**Изменено 13.10:** аутентификация клиента в Entra — сертификат (`private_key_jwt`), закрытый ключ создан и хранится только на VPS (`/etc/varde/entra/`), client secret не используется; регистрация «Varde» и группа «Varde admins» (role-assignable, без владельцев) созданы, назначение обязательно.

## Контекст
Трое пользователей, ролей нет. Fable предлагал постоянного локального break-glass админа; Astra возразила: второй публичный механизм входа — отдельная поверхность атаки и обслуживания (лимиты, ротация пароля, lockout).

## Решение
- OIDC через Microsoft Entra; допуск по членству в одной группе; сессия в HttpOnly Secure cookie; logout.
- Break-glass: локальный вход существует в коде, но выключен по умолчанию. Включается переменной окружения на ограниченное время (пакет этапа 0: окно не дольше 4 ч), слушает только локально на хосте VPS — не сетевой порт: в пакете этапа 0 это Unix socket в каталоге хоста, потому что контейнер подключён к общим сетям Atlas и TCP-порт был бы виден соседним контейнерам; доступ через `ssh -L` на socket; сессия живёт не дольше часа и принимается только этим listener; включение и каждый вход пишутся в AuditLog с именем оператора. С публичного адреса endpoint отвечает 404.
- Кто имеет SSH на VPS — тот и может активировать аварийный доступ; ответ на вопрос Astra «кто восстанавливает систему без Oleksandr» уточняет круг SSH-доступа, не архитектуру входа.
- Экран ведущего на семинаре не зависит от Entra: presenter-token выпускается заранее на семинар (этап 3). Область token: open/close/release вопросов только этого live poll и чтение его released-результатов; ничего другого в API. Срок: день семинара ± 1; отзыв из админки; выпуск и отзыв в AuditLog. Тест этапа 3: сценарий семинара (открыть вопрос, собрать ответы, закрыть, показать) проходит с отключённым mock-Entra.

## Альтернативы
Постоянный публичный break-glass с TOTP (ещё один механизм аутентификации); только Entra без аварийного пути (недоступность при сбое регистрации приложения).

## Последствия
Регистрация приложения в Entra требует админа тенанта — блокер этапа 0. Цена изменения: S.
