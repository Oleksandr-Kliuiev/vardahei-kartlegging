# UX-ревью админки Varde и проверка плагинов Design / Intuitive Software Design (17.10.2026)

Цель: проверить, полезны ли два только что установленных плагина, и заодно получить список реальных UX-дефектов админки. Продуктовый код не менялся, ничего не коммитилось.

## Как проверяли

- Стек: e2e-харнесс (`apps/admin/e2e`), одноразовый Postgres 17 на `127.0.0.1:55498`, mock Entra. Данные — фикстуры e2e (названия раундов вида `e2e-admin-…-dashboard`, «Syntetisk admin kunde»), поэтому реальных наполненных экранов нет: дашборд почти пустой, события в журнале — тестовые.
- Скриншоты 9 экранов (`/admin`, `rounds`, `dashboard`, `surveys`, `findings`, `seminars`, `reports`, `export`, `deletion`) на 1440 и 390 px, light. Просмотрены глазами: home, rounds, dashboard, reports, export, deletion на 1440; home и deletion на 390. **surveys, findings, seminars — только заснято и промерено DOM-скриптом, на глаз не разбирались.**
- DOM-замеры (Playwright `evaluate`): h1/main, горизонтальный скролл, подписи полей, размеры целей, мелкий шрифт, `document.title`, первый Tab-фокус.
- Не проверялось: тёмная тема, клавиатурный обход всех экранов, скринридер, реальные данные, запуск форм (ничего не отправлялось и не удалялось). Контраст проверен только по токенам `tokens.css` вручную (см. ниже), не по рендеру.
- Сценарии разбирались по скриншотам и коду (`round-client.tsx`, `launch-form.tsx`, `deletion-page.tsx`, `widgets.tsx`), без прогона мутаций.

## Находки (по приоритету)

Серьёзность: **S1** мешает выполнить задачу / риск ошибки с последствиями, **S2** заметное трение, **S3** шлифовка. Источник: `[скилл]` / `[я]` — кто навёл.

### S1

1. **Задача «кто не ответил → отправить напоминание» не решается в интерфейсе.** [task-walkthrough]
   - Экран: Oversikt, Kundar og rundar. Доказательство: Oversikt показывает только счётчики на клиента («0 av 12», «Kvar stoppar folk: økter starta, 0 svar sende»); поимённого списка нет (по дизайну: админка знает только число tilsette, не список). В коде нет напоминаний (grep `påminn|reminder` — только `archive-reminder.tsx`, он про архив). Единственное действие отправки — «Send ut» в карточке клиента раунда, это та же инвайт-версия текста.
   - Фикс: честно сказать это в UI («Varde veit ikkje kven som ikkje har svart — berre kor mange. Be leiaren minne på…»); добавить вариант текста «Påminning» рядом с инвайтом (языки nn/en как сейчас) и подсказку, когда напоминать (frist, % ответов). Решение о списке по людям — отдельное продуктовое (приватность: инициалы видит только Vardahei IT).

2. **«Send ut» — кнопка с обещанием, которого Varde не выполняет.** [task-walkthrough, ux-copy] Экран: Kundar og rundar, карточка клиента (`round-client.tsx:215`). Админ ожидает отправку письма; на деле раскрывается текст и ссылка «Kopier tekst / Kopier lenkje», отправляет человек сам. В остальных местах продукта это честно сказано (Rapportar: «Varde sender ingenting sjølv»), здесь — только мелким абзацем после клика. Фикс: «Invitasjonstekst og lenkje» / «Hent tekst til utsending»; одна фраза о том, что текст отправляет руководитель клиента, перед кликом.

3. **Удаление по запросу сотрудника: порядок и вход неудобны, превью не называет, что удаляется.** [task-walkthrough, decision-support] Экран: Sletting (`deletion-page.tsx`).
   - По умолчанию выбрано «Valde innsendingar» (ввод ID-шников), а типичный запрос — «удалите мои ответы»: нужна область «Ein person (initialar)». Админ не знает ID, знает инициалы/клиент.
   - Превью («N vanlege svar og M leiarsvar. Til saman K») не повторяет, что именно выбрано (клиент, инициалы, раунд). Инициалы не уникальны (F1/K0) — риск удалить тёзку; превью не показывает даты/раунды затронутых ответов.
   - Кнопка «Vis førehandsvising» серая без объяснения, чего не хватает (ID-ар и grunngjeving).
   - Что сделано хорошо: превью → удержание кнопки 1,2 с, поддержка Space/Enter, подсказка и `aria-describedby`, фраза «Publiserte samla tal blir verande».
   - Фикс: порядок областей по частоте (person первой), эхо выбора в превью («Initialar AB hos Daco, alle rundar: 3 svar: …»), перечень раундов/дат, причина disabled; после удаления показать квитанцию (что/когда/сколько) — понадобится для ответа субъекту данных.

### S2

4. **Заголовок вкладки «Varde» на всех страницах.** [я, DOM-замер; WCAG 2.4.2] `document.title` = «Varde» на девяти экранах; только отчёт ставит своё. Фикс: «Oversikt – Varde» и т.п. из `SECTIONS`.

5. **Старт раунда: выбор версии и две похожие формы.** [decision-support] Экран: Kundar og rundar. «Vel publisert versjon» — просто список без даты/числа вопросов/что изменилось; рядом «Start ein runde» и «Ny tom runde» без объяснения, чем «тома» отличается. Старт-кнопка серая, пока не выбран клиент, без подсказки. Хорошо: четыре нумерованных шага, «Vel alle / Vel ingen». Фикс: в опциях версий — дата публикации и число вопросов; подпись под «Ny tom runde» (когда нужна); подсказка у disabled-кнопки.

6. **Страница Kundar og rundar — 4100 px на 1440, всё подряд.** [design-critique, я] Управление клиентами (форма, табличка) стоит выше списка раундов, закрытые и открытые раунды перемешаны, 97 интерактивных элементов. Основное действие (старт) — в правой колонке. Фикс: фильтр «Opne / Avslutta», закрытые свернуть; сегмент «Kundar» отдельным табом или вниз.

7. **Статусы «Stengd» и «Avslutta» на одной карточке + «Steng» и «Avslutt heile runden».** [ux-copy] Клиент «Stengd», раунд «Avslutta» — разные понятия (клиент закрыт / раунд завершён) названы близко. Фикс: либо единый термин, либо пояснение в title/tooltip; «Avslutt heile runden» не соседствует с «Steng» без различия.

8. **«Ny kode» vs «lenkje».** [ux-copy] Кнопка «Ny kode», подтверждение «Gamle lenkjer sluttar å verke. Stadfest», в тексте «Lenkje til kartlegginga». Админ не обязан знать, что код = часть ссылки. Фикс: «Ny lenkje» + то же подтверждение. Подтверждение по двойному клику уже хорошее: описывает последствие.

9. **Отчёт клиенту: нет передачи дальше.** [task-walkthrough] Экран: Rapportar. Поток: Runde → Kunde → переключатель «Eg har lese gjennom rapporten» → «Lagre som PDF». Дальше человек сам. Нет: предлагаемого имени файла, готового текста сопроводительного письма, отметки «отправлено», второго проверяющего (переключатель — самоаттестация). Фикс: хотя бы имя файла `<klient>-<runde>.pdf` и отметка «Sendt til kunden <dato>» в карточке раунда; решить, нужен ли второй проверяющий (Asbjørn).

10. **Мобильный 390: таблица «Framdrift» на Oversikt обрезана внутри карточки без признака прокрутки.** [я] Видно столбец «Svar / oppslutning» наполовину. DOM: `TABLE.framdrift` выходит за ширину (скролл внутри контейнера, страница не скроллится — хорошо). Фикс: тень/градиент края или стековая раскладка строк на узком экране. Аналогично `TABLE.rute` на дашборде.

11. **Журнал «Siste hendingar»: сырые ключи и ID.** [я] «system privacy.release.auto round:f3cb2074-…», «entra:oid-1 leader.read client:e2e-…». Для админа нечитаемо; на 390 переносится по символам. Фикс: человеческие подписи («Automatisk frigjeving av tal», имя клиента вместо UUID). Формат даты в моём Chromium вышел en-US («10/17/2026, 8:50:03 AM») при `toLocaleString('nn-NO')` (`rounds-page.tsx:107`): скорее артефакт окружения Playwright, в обычном Chrome должно быть nn-NO — **не подтверждено**, стоит глянуть в реальном браузере.

### S3

12. **Мелкий текст:** на дашборде 8 px (×8 узлов) и 11 px; на Funn 11/11,5 px; 11 px на всех экранах (моноширинные «ARBEID/INNHALD», метки). Фикс: минимум 12 px для читаемого текста; 8 px — проверить, что это иконки/метки на диаграммах, а не текст.

13. **Цели касания в сайдбаре 37–38 px по высоте** при ширине 231–275. [accessibility-review; нюанс: плагин считает это нарушением 2.5.5 «AA», на деле AAA] По WCAG 2.2 AA (2.5.8, 24 px) проходит; для мобильного тач-меню 44 px было бы удобнее. Остальные «малые» цели — чекбоксы/радио и ссылки в тексте, отдельно не разбирал.

14. **Контраст (вручную по токенам):** `ink-muted` `#6b6e70` на белом 5,14:1 — ок; `graa-500` `#87898c` на белом 3,51:1 — не годится для текста (проверить, где используется); белый на `blaa-400` 2,53:1; цвет зон на тонированном фоне, например `sone-gul` `#e2ad12` на `#fdf3d3` 1,85:1 — только если такая пара применяется как текст (в рендере не проверял). Disabled-кнопка «Lagre som PDF» на `opacity .45` — disabled формально освобождён, но причину не видно (нужны Runde+Kunde+переключатель).

15. **Фокус и структура — в порядке.** По замерам: один `h1` и один `main` на каждом экране, у каждого поля есть подпись (0 без label), страница не скроллится по горизонтали, первый Tab получает видимый outline 2 px. Нет «skip link» («Hopp til innhald») — не нашёл в коде. Полный обход клавиатурой не делал.

16. **Копирайтинг (нюношк).** Букмол-слипов в `*.tsx` не найдено (grep по маркерам; «også», «mellom» допустимы). Замечания по тону: «Eit menneske sjekkar og sender han sjølv» — звучит как «ИИшность», проще «Du sjekkar og sender han sjølv»; «Vis førehandsvising» → «Førehandsvis»; «Felles del» в KPI «Svar i runden» без пояснения (общая vs руководительская часть); «Svarar no» ок. Строка «– økter starta, 0 svar sende» на Oversikt выглядит как оборванная фраза с ведущим тире.

## Что работает хорошо (не трогать)

- Нумерованные шаги старта раунда; «Vel alle / Vel ingen».
- Двойное подтверждение «Ny kode» с описанием последствия; удаление через превью + удержание, с клавиатурной поддержкой.
- Честные плашки «Varde sender ingenting sjølv» на Rapportar/Seminar; пустое состояние предпросмотра («Vel ein kunde for å sjå rapporten.»).
- Скрытие малых групп (< 3) с пояснением, что «–» значит.
- Токены/тёмная тема продуманы, один `h1`, подписи полей на месте.

## Вердикт по плагинам

Стоило:
- **user-task-walkthrough** — самый полезный: дисциплина «что пользователь знает/видит/ожидает» и явное «неизвестно» нашла две главные проблемы, которые не видно при просмотре скриншотов (нет сценария напоминания, «Send ut» обещает отправку).
- **decision-support-design** — полезен для выбора версии/области удаления и дефолтов.

Скорее общий шум:
- **design-critique** и **ux-copy** — шаблоны с общими принципами; хороши как чек-лист, но без знания продукта (нюношк, «Varde ничего не шлёт») и не дают находок сами по себе.
- **accessibility-review** — справка WCAG 2.1 с ошибкой в уровне 2.5.5; свои замеры дали больше. Для проекта нужен 2.2 AA.
- **behavioral-evaluation** — не для этой задачи (это инструмент оценки самого плагина).

Практика: оставлять в процессе `user-task-walkthrough` (+ `decision-support-design` для форм с выбором и необратимыми действиями) для новых экранов; а механические проверки (заголовки, подписи, размеры, мелкий шрифт, overflow) лучше закрепить в `ui-layout-audit`: добавить проверки `document.title` на уникальность, минимальный размер шрифта 12 px и отсутствие 8–11 px текста, обрезанные таблицы на 390 без индикатора прокрутки, сырые ID/ключи в видимом тексте.

## Ограничения

Данные — фикстуры, не реальные раунды; тёмная тема, клавиатурный обход и скринридер не проверялись; surveys/findings/seminars на глаз не разобраны; про даты/локаль (п. 11) нужна проверка в реальном браузере; выводы task-walkthrough — гипотезы без пользовательских тестов (на живых людях не проверялись).
